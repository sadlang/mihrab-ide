# 🕌 محراب (mihrab-ide)

> محرّر/بيئة تطوير **مستقلّة** للغة ص، مبنيّة على **VSCodium-مرقَّع** —
> لا تفرّع عميق (نمط Cursor) ولا تجميد (hard fork).

محراب يحزم سلسلة أدوات ص (إضافة المحرّر + خادم LSP + `sad-build`/`sad-run`) بتهيئة
صفريّة، ويقدّم **دعم RTL من الدرجة الأولى** الذي يستحيل تحقيقه كاملًا بطبقة إضافة وحدها.

- **الحالة:** م0 (بناء أساس قابل للتكرار) — قيد التأسيس.
- **الرؤية:** خاصّ مبدئيًّا حتى نضوج م0–م1، ثم يُفتح (قلب مفتوح، MIT).
- **مصدر حقيقة التخطيط:** [`sadlang-planning/projects/mihrab-editor/`](https://github.com/sadlang/sadlang-planning/tree/main/projects/mihrab-editor)
- **المقترح (RFC):** [`sadlang/rfcs#21`](https://github.com/sadlang/rfcs/pull/21) (`tools/mihrab`).
- **المعلم الفيدراليّ:** `M-mihrab-1.0` (المرحلة الثالثة).

> هذا المستودع لا ينسخ خطّة التخطيط ولا يكرّرها — يشير إليها. حقيقة المراحل والتصميم
> تعيش في `sadlang-planning`؛ هنا **الكود والبناء** فقط.

## ما هو نموذج «VSCodium-مرقَّع»؟

محراب **لا يحتفظ بنسخة من ملايين أسطر VS Code**. بدلًا من ذلك يحتفظ بـ:

1. **تثبيت المنبع** ([`upstream.json`](upstream.json)) — إصدار VSCodium/VS Code المعتمَد.
2. **رُقَع ذرّيّة** ([`patches/`](patches/)) تُطبَّق على المنبع وقت البناء (الطبقة الثالثة).
3. **تجاوزات المنتج** ([`product-overrides/`](product-overrides/)) — الهويّة والإعدادات (الطبقة الثانية).
4. **بناء قابل للتكرار** ([`build/`](build/)) يستنسخ المنبع المثبَّت، يطبّق ما سبق، ويُنتج «محراب».

هذا يطابق نموذج VSCodium نفسه: **ملكيّة الهويّة دون تباعد قاعدة الشيفرة**.

تفصيل النموذج: [`docs/architecture/three-layer-model.md`](docs/architecture/three-layer-model.md).

## الطبقات الثلاث (مؤشّر الصحّة)

| الطبقة | الموضع | دَيْن الدمج |
|--------|--------|------------|
| 1 — إضافة محزومة | معظم منطق ص (عبر LSP) | شبه معدوم |
| 2 — تجاوز بناء | `product-overrides/` (الهويّة، الإعدادات) | منخفض |
| 3 — رُقعة نواة | `patches/` (RTL النواة، إزالة التتبّع) | مرتفع — يُحتوى |

**مؤشّر صحّة المشروع = عدد رُقَع الطبقة الثالثة.** كلّما قلّ، قلّ دَيْن الصيانة.
