# اقتراحاتُ تعديلاتِ المصدر — ما يجب أن يدعمه المنبعُ أصالةً لنتخلّى عن رُقَعنا

> **الغرض.** كلُّ رُقعةٍ في محراب دَينٌ: تُطبَّق على مصدرٍ لا نملكه، وتنكسر متى انجرفت
> مرساتُها، ويجب أن تُراجَع مع كلّ ترقيةِ إصدار. هذا التقريرُ يقلب النظرَ إلى الجهة
> الأخرى: **ماذا لو دعم المنبعُ الميزةَ أصالةً؟** لكلّ رُقعةٍ هنا: أينَ تُطبَّق، وما
> الشكلُ المنبعيُّ الذي يُغنيها، وهل يُسقطها ذلك كلَّها أم بعضَها.
>
> **قاعدةُ التحديث.** كلُّ رُقعةٍ جديدةٍ تُضاف إلى محراب ⇒ سطرٌ في الجدول **و** قسمٌ
> مفصَّل هنا. رُقعةٌ بلا مقترحٍ منبعيٍّ = دَينٌ بلا خطّةِ سداد.

## م-١) اتّجاهٌ منطقيٌّ لقشرة workbench

**الحالُ في المنبع.** لا يدعم VS Code واجهةً من اليمين. لغاتُ الحزم العربيّة والعبريّة
تُترجِم النصَّ ويبقى التخطيطُ يسارًا. فما نفعله ليس «تفضيلًا» بل سدُّ نقصٍ كامل.

**ما تفعله رُقَعنا.**

| الرُقعة | الملفّ المنبعيّ | التعديل |
|---|---|---|
| `patch_workbench_rtl` | `vs/workbench/browser/workbench.ts` | `dir="rtl"` على `.monaco-workbench` + استيرادُ ورقتنا |
| `patch_menubar_rtl` | `vs/base/browser/ui/menu/menubar.ts` | المنسدلةُ تُثبَّت بحافّتها اليمنى بدل `style.left` |
| `patch_menu_rtl` | `vs/base/browser/ui/menu/menu.ts` | اتّجاهُ التعاقب الفرعيّ + **قواعدُ CSS داخل `getMenuWidgetCSS`** لأنّ القوائم في Shadow DOM |
| `patch_splitview_rtl` | `.../splitview/splitview.ts` | إزاحةٌ تراكميّة بـ`right` بدل `left` |
| `patch_sash_rtl` | `.../sash/sash.ts` | المقبضُ العموديّ بـ`right` |
| `patch_gridview_marker` | `.../grid/gridview.ts` | وسمُ `mihrab-grid-sv` لتمييز splitview الشبكة (تُدار بإعادة ترتيب العقد فلا تُقلَب) |
| `patch_tabsdrop_rtl` | `.../editor/multiEditorTabsControl.ts` | فهرسُ الإفلات والمؤشّرُ البصريّ — **عطبٌ وظيفيّ**: التبويب يهبط في مكانٍ خاطئ |

**المقترحُ المنبعيّ.**

1. **اتّجاهُ التخطيطِ إعدادٌ أوّليّ الدرجة**، يُحلّ في العمليّة الرئيسة مع اللغة:

   ```jsonc
   // product.json
   "layoutDirection": "rtl"          // أو يُشتَقّ من defaultLocale
   // settings.json
   "workbench.layoutDirection": "auto" | "ltr" | "rtl"   // auto ⇐ من لغة الواجهة
   ```
   ويُسنَد على حاوية workbench قبل بناء الأجزاء (نفسُ الموضع الذي نرقّعه).

2. **الخصائصُ الفيزيائيّةُ تُستبدَل بالمنطقيّة** في ودجات `vs/base/browser/ui`: ‏`left/right`
   ⇐ `inset-inline-start/end`، ‏`margin-left` ⇐ `margin-inline-start`، وهكذا. أكثرُ
   من نصف ورقتنا (‏٩٥١ سطرًا، قواعدُها مرقَّمةٌ حتّى ٣٥) ليس إلّا إبطالَ خصائصَ فيزيائيّةٍ
   مكتوبةٍ في المنبع.

3. **حساباتُ الموضع بـJavaScript تقرأ الاتّجاه**: ‏`splitview` و`sash` و`menubar`
   تحسب الإزاحةَ تراكميًّا من اليسار بافتراضٍ مبثوثٍ لا مُصرَّح. الشكلُ المطلوب:

   ```ts
   const rtl = getComputedStyle(this.el).direction === 'rtl';
   const edge = rtl ? 'right' : 'left';
   container.style[edge] = `${offset}px`;
   ```
   وهو ما نفعله حرفيًّا — لكن من الخارج.

4. **منطقُ الإفلات يفصل الجهةَ الفيزيائيّة عن الفهرس المنطقيّ**:
   ```ts
   // بدل: if (location === 'right') targetIndex++;
   const after = rtl ? location === 'left' : location === 'right';
   if (after) { targetIndex++; }
   ```
   هذا **إصلاحُ عطبٍ لا ميزة**: المنبعُ اليوم يخلط الفهرسَ بالجهة، وسيصير خاطئًا لديه
   في اللحظة التي يدعم فيها RTL.

5. **‏`getMenuWidgetCSS` تُولِّد قواعدَ الاتّجاه**: طالما القوائمُ في Shadow DOM، لا
   ورقةَ مستندٍ تبلغها. الاتّجاهُ يجب أن يُولَّد حيث يُولَّد باقي نمطِ القائمة.

**ما يسقط.** الرُقَعُ السبعُ كلُّها، ومعظمُ قواعد الورقة (تبقى قواعدُ الهويّة والطباعة).

## م-٢) اتّجاهُ النصّ في Monaco كخيارِ محرّر

**الحالُ.** بنيةُ Monaco الداخليّة إحداثيّاتٌ **فيزيائيّة LTR**. قلبُ الحاوية بـ`dir=rtl`
يُطيِّر النصَّ خارجَ الشاشة (قِسناه بـCDP على بناءٍ فاشلٍ أوّل). فالمحرّرُ يملك آليّةَ
سطرٍ RTL مدمجةً (`viewLine.ts` يضع `dir="rtl"` للسطر، والمؤشّرُ وhit-test يتبعانها)
**لكن لا خيارَ عامًّا يُشغّلها**: ‏`_getTextDirection` يُقرّر بمحتوى السطر وحده.

**ما كنّا نفعله.** ‏`patch_editor_rtl` على تسعة ملفّات: ‏`viewModelImpl` (اتّجاهُ السطر
افتراضيًّا RTL) · `margin.ts` (المزراب يمينًا) · `editorScrollbar.ts` (المحتوى) ·
`minimap.ts` (الخريطة يسارًا) وغيرها.

**ما نفعله اليوم.** لا رُقعةَ محرابٍ أصلًا: `patches/core/010-editor-text-direction.patch`
— تعديلٌ منبعيٌّ إنجليزيٌّ لا يذكر محرابًا، يُطبَّق بـ`git apply --3way` بعد الـreset، ويسقط
بلا أثرٍ يوم يُدمَج. ومحراب يضبط `editor.textDirection: rtl` في `configurationDefaults`
بامتداد `mihrab-shell` (الطبقة الأولى، لا رقعة) — احتياطًا لا حاجةً: واجهةُ محراب عربيّة،
و`auto` تتبع لغةَ الواجهة فتُعطي RTL بلا إعداد.

**المقترحُ المنبعيّ.**

```ts
// vs/editor/common/config/editorOptions.ts
textDirection: 'auto' | 'ltr' | 'rtl'   // auto = السلوكُ الحاليّ (من محتوى السطر)
```
يُستهلَك في ثلاثة مواضعَ لا أكثر:

```ts
// viewModelImpl.ts — نقطةُ القرار الوحيدة
private _getTextDirection(line: string): TextDirection {
  const opt = this._configuration.options.get(EditorOption.textDirection);
```

## م-٣) لغةٌ افتراضيّةٌ للمنتج تُحلّ قبل أوّل رسم

**الحالُ.** حزمةُ اللغة لا تُفعَّل إلّا بعد أن يُسجّلها مسحُ الإضافات في
`languagepacks.json` — **بعد أوّل إقلاع**. فأوّلُ فتحٍ إنجليزيٌّ دائمًا، والثاني عربيّ.
ولا سبيلَ لتوزيعِ منتجٍ لغتُه الافتراضيّةُ غيرُ الإنجليزيّة.

وأثرٌ ثانٍ أخطر: خبزُنا للعربيّة يتجاوز حلَّ اللغة، فيبقى `configuration.nls.language`
غيرَ معرَّفٍ، ويكتب `setupNLS`:

```ts
let language = configuration.nls.language || 'en';
window.document.documentElement.setAttribute('lang', language);   // ⇐ lang="en"
```

فيصير المستندُ **يكذب**: واجهةٌ عربيّةٌ بالكامل و`<html lang="en">`. وهذا يكسر ثلاثةَ
أشياءَ لا تجميلًا واحدًا: نطقُ قارئات الشاشة (‏WCAG 3.1.1)، ومحدِّدُ `:lang(ar)` — الذي
مات صامتًا عندنا فعلًا (‏[AR-03]، اجتاز L0 وL2 وكان شيفرةً ميّتةً حتّى كشفه CDP)، وتلميحُ
اللغة لمحرّك تشكيل النصّ.

**المقترحُ المنبعيّ.**

```ts
// vs/base/node/nls.ts (أو main.ts:getUserDefinedLocale)
// أسبقيّة: --locale ← argv.json ← product.defaultLocale ← لغةُ النظام ← en
const locale = argvLocale ?? product.defaultLocale ?? osLocale ?? 'en';

// workbench.ts (مُمهِّد النافذة)
const language = configuration.nls.language || product.defaultLocale || 'en';
document.documentElement.setAttribute('lang', language);
document.documentElement.setAttribute('dir', getTextDirectionForLocale(language));  // ⇐ ومع م-١
```

وسطرُ `dir` هذا يُسقط شطرًا من م-١ كذلك: تصريحٌ واحدٌ في المُمهِّد أنظفُ من رقعةٍ
في `workbench.ts` وورقةِ أنماطٍ مستورَدة.

**ما يسقط.** ‏`patch_main_locale` و`patch_html_lang` كلتاهما. ويبقى `bake_nls_arabic`
مطلوبًا حتّى يدعم المنبعُ **حزمةَ لغةٍ مدمجةً تُحلّ في الإقلاع الأوّل** (م-٩).

## م-٤) عناوينُ الإعدادات المشتقّة حسابيًّا

**الحالُ.** عناوينُ لوحة الإعدادات ليست سلاسلَ مترجَمة: لا مدخلَ لها في NLS ولا في
حزمة اللغة. تُشتَقّ وقتَ التشغيل:

```ts
wordifyKey('editor.formatOnSave')  →  'Editor › Format On Save'
```

فيبقى في واجهةٍ عربيّةٍ بالكامل **سطرٌ لاتينيٌّ فوق كلّ إعداد** ووصفُه تحته عربيّ.
ولا طبقةَ أدنى تصله: لا سلسلةَ ترجمةٍ تتّسع له، ولا إعدادَ يخصّصه، ولا CSS تُصلحه
(النصُّ نفسُه إنجليزيّ — ليست مشكلةَ اتّجاه).

**عطبُ عزلٍ منفصلٌ يصيب المنبعَ نفسَه.** أيًّا كانت الترجمة، وضعُ عنوانٍ لاتينيٍّ داخل
فقرةٍ عربيّةٍ بلا عزلٍ ثنائيِّ الاتّجاه يُخرج النقطتين والفواصلَ إلى الجهة الخطأ. هذا
**عطبُ bidi في المنبع يصيب كلَّ لغةٍ RTL**، ولو لم يوجد محرابٌ أصلًا.

**المقترحُ المنبعيّ.**

```ts
// vs/workbench/contrib/preferences/browser/settingsTreeModels.ts
export function settingKeyToDisplayFormat(key: string, groupId = '', …) {
  …
  // 1) خطّافُ ترجمة: يسمح لحزمة اللغة/المنتج بتقديم صورةٍ مترجَمةٍ للمقطع
  const label = settingLabelProvider?.(trimmed) ?? wordifyKey(trimmed);
  // 2) عزلُ الاتّجاه في **النصّ** لا في CSS — لأنّه يُسنَد إلى aria-label ونصِّ الروابط
  return isRTLLocale ? `⁨${label}⁩` : label;
}
```

وبندان لا بدّ منهما مع أيٍّ منهما:

- **البحث**: بحثُ الإعدادات يطابق المفتاحَ والوصفَ و`keywords` ولا يطابق العنوانَ
  المعروض. فبلا إلحاقِ الصورةِ المعروضةِ بالكلمات المفتاحيّة، يقرأ المستخدمُ عنوانًا
  مترجَمًا ويكتبه **فلا يجد شيئًا**.
- **مسارٌ ثانٍ**: إعداداتُ الامتدادات ذاتُ `title`/`categoryLabel` لا تمرّ بـ`wordifyKey`
  أصلًا — فأيُّ حلٍّ في الاشتقاق وحده يترك نصفَ اللوحة خارجَه (وهذا حدُّ رقعتِنا
  المعلومُ اليوم).

**ما يسقط.** ‏`patch_settings_labels` ووحدةُ `mihrabSettingsLexicon.ts` وقاعدةُ CSS ‏٣٥،
ومعها **انحرافُنا المعلوم** في اختبار المنبع `settingsTreeModels.test.ts` (يتوقّع `'Foo'`
ويحصل على `'⁨Foo⁩'`).

**تغطيتُنا اليوم** — للسياق لا للمفاخرة: ‏٦٣٫٩٪ من مقاطع الفئات و٥٨٫٠٪ من عناوين
الأقسام، على ‏١٥٢٣ مفتاحًا محصودًا. الباقي إنجليزيٌّ عمدًا (أسماءُ أعلامٍ لا تُترجَم:
‏Git، Npm، Vite) بقاعدة «لا نصفَ ترجمة».

## م-٥) اسمُ مجلّدِ تهيئةِ المشروع قابلٌ للاشتقاق

**الحالُ.** المنبع يُصرِّح `FOLDER_CONFIG_FOLDER_NAME = '.vscode'` **مرّةً**، ثمّ يكتب
`'.vscode'` سلسلةً حرفيّةً في نحوِ ثلاثين موضعًا لا تمرّ بالثابت: إنشاءُ `tasks.json`،
ومسارُ `launch.json`، وتوصياتُ الامتدادات، وقصاصاتُ مساحة العمل، وتسميةُ `mcp.json`،
وتجاوزُ ترميز UTF-8، ونمطُ الموافقة التلقائيّة في الوكيل.

فتبديلُ الثابتِ وحدَه يُنتج أسوأَ حالة: **يقرأ من مكانٍ ويكتب في آخر**، بلا خطأٍ ولا
سجلّ. عطبٌ صامت. لذلك رقعتُنا في ستّةَ عشرَ ملفًّا.

**المقترحُ المنبعيّ.** ليس «اقبلوا `.محراب`» — بل:

1. **كلُّ موضعٍ يمرّ بالثابت.** إصلاحُ نظافةٍ مستقلٌّ عن أيّ منتج، ويُختبَر بحارسٍ
   ساكنٍ بسيط: لا سلسلةَ `'.vscode'` حرفيّةً خارج التصريح.
2. **الثابتُ يُشتَقّ من هويّة المنتج**:
   ```jsonc
   // product.json
   "folderConfigFolderName": ".محراب",
   "folderConfigFolderCompat": [".vscode", ".mihrab"]   // تُقرَأ ولا يُكتَب فيها
   ```
3. **دمجٌ بأسبقيّةٍ عند وجود أكثرَ من واحد** (`ConfigurationModel.merge`) فلا يضيع
   إعدادٌ صامتًا، و**الكتابةُ إلى الموجودِ فعلًا** فلا يكتسب مشروعٌ قديمٌ مجلّدًا ثانيًا.

**ما يسقط.** الرُقعةُ كلُّها ووحدتا `mihrabConfigFolder.ts` و`mihrabConfigFolderResolve.ts`.

**حدٌّ يبقى في الحالتين.** ‏`CachedFolderConfiguration` (مسارُ الاتّصال البعيد/الوِب)
يُخزّن المجلّدَ الأساسيَّ وحده، فأوّلُ إقلاعٍ بلا اتّصالٍ قد يفقد طبقةَ التوافق.

## م-٦) افتراضاتُ إعداداتٍ من هويّة المنتج

**الحالُ.** الحوارُ المشروط (احفظ/لا تحفظ/إلغاء) يحجب التطبيقَ كلَّه حتى يُجاب، وافتراضُه:

```ts
'window.dialogStyle': { 'default': 'native', 'scope': ConfigurationScope.APPLICATION }
```

فمحرابٌ على ويندوز — بلا إعدادٍ من المستخدم — يعرض حوارَ نظامِ التشغيل: نصُّه بلغة
ويندوز، اتّجاهُه LTR، وترتيبُ أزراره ليس ترتيبَنا. أشدُّ لحظاتِ الواجهة إلحاحًا (لحظةُ
فقدِ عمل) تخرج من التعريب كلِّه.

**جرّبنا الطبقةَ الأدنى وفشلَت — قياسًا لا ظنًّا**: ‏`configurationDefaults` من إضافةٍ
لا يغلب نطاقًا تطبيقيًّا (‏`APPLICATION`). نفسُ العيّنة مع الإضافة ردّت `0 حوار`، ومع
الإعداد في ملفّ المستخدم ردّت `1` بأزرارٍ عربيّة.

**المقترحُ المنبعيّ.** أن يُطبِّق المنبعُ `configurationDefaults` من `product.json`
بأسبقيّةٍ **فوق افتراضِ المنبع ودون تفضيلِ المستخدم**، وأن تشمل النطاقَ التطبيقيّ:

```jsonc
// product.json
"configurationDefaults": { "window.dialogStyle": "custom" }
```

> **غيرُ مقيس.** لم نتحقّق هل تدعم إصداراتٌ أحدثُ من ‏1.121 هذا الحقلَ في `product.json`
> ولا ما نطاقُه إن دُعم. إن ثبت أنّه مدعومٌ ويشمل `APPLICATION`، تسقط الرُقعةُ **فورًا**
> بلا حاجةٍ إلى مقترحٍ أصلًا — وهذا أوّلُ ما يجب فحصُه في هذا الملفّ.

**ما يسقط.** ‏`patch_dialog_style`، وكلُّ افتراضٍ تطبيقيٍّ نحتاج تغييرَه مستقبلًا.

## م-٧) حجبُ الجولاتِ المدمجة

**الحالُ.** الجولاتُ المدمجة (‏`Setup` · `SetupWeb` · `Beginner`) تُسجَّل برمجيًّا من
ثابتٍ مستورَد، ونقطةُ الامتداد **تُضيف فقط ولا تحجب**. فتزاحم جولةَ محراب على صدارة
أوّلِ سطحٍ يراه المستخدم، وتُبقي اسمَ المنبع وصوتَه الإنجليزيّ فيه.

وأقربُ بديلٍ من الطبقة الثانية — إخفاءٌ بـCSS — علاجٌ بصريٌّ يُبقي الجولةَ مسجَّلةً
وقابلةً للفتح من لوحة الأوامر.

**المقترحُ المنبعيّ.**

```jsonc
// product.json
"hiddenWalkthroughs": ["Setup", "SetupWeb", "Beginner"]
```
تُرشَّح في `registerWalkthroughs` قبل التسجيل. ‏**بالمعرّف لا بـ`isFeatured`**: المعرّفاتُ
ثابتةٌ عبر الإصدارات، والعَلَمُ يتبدّل — ولو رُشِّح بالعَلَم لسقطت `SetupAccessibility` معها،
وهي محتوى وصولٍ لا يُعوَّض.

**ما يسقط.** ‏`patch_walkthroughs_drop`.

## م-٨) ترويسةُ صفحةِ الترحيب من هويّة المنتج

**الحالُ.** الترويسةُ مبنيّةٌ برمجيًّا بـ`dom.$` لا قالبًا، والعنوانُ الفرعيّ
(«‏Editing evolved») سلسلةٌ في الشيفرة. فلا سبيلَ من إعدادٍ أو ورقةِ أنماطٍ لإضافة عنصر
شعارٍ أو تبديلِ الجملة.

**المقترحُ المنبعيّ.**

```jsonc
// product.json
"welcome": { "tagline": "…", "markAsset": "resources/welcome-mark.svg" }
```

مع عنصرَي DOM فارغَين مُسمَّيَين في الترويسة (`.welcome-mark` و`.welcome-pattern`) يملؤهما
المنتجُ أو يتركهما — فتصير الزخرفةُ والشعارُ ورقةَ أنماطٍ لا رقعةَ شيفرة.

**ما يسقط.** ‏`patch_welcome_rtl`؛ وتبقى قواعدُ الورقة ‏١٧·١٩·٣٢·٣٣ (وهي هويّةٌ بصريّةٌ

## م-٩) تراكبُ ترجمةٍ للامتدادات المدمجة

**الحالُ (اكتُشف بتحقّقٍ حيٍّ بـCDP).** حين تكون حزمةُ اللغة نشطة — وهي كذلك دائمًا في
محراب — تحلّ النواةُ ترجمةَ بيانِ الامتداد هكذا:

```ts
const id = `${publisher}.${name}`;
const c = nlsConfig.translations[id];
if (c) { values = read(c).contents.package; }        // ⇐ مسارُ حزمة اللغة
else   { values = read(`package.nls.${locale}.json`); }  // ⇐ ارتدادٌ فقط حين لا حزمة
```

أي أنّ `package.nls.<locale>.json` **يُتجاوَز كلّيًّا** لأيّ امتدادٍ مُدرَجٍ في خريطة
حزمة اللغة. فمن أراد إكمالَ تغطيةٍ ناقصةٍ (حزمةُ ‏1.85 تغطّي نحوَ ٢٣٪ من مفاتيح البيان)
اضطُرّ إلى إعادة بناء `contents.package` كلِّه — وهو ما نفعله.

**المقترحُ المنبعيّ.** أن يكون الحلُّ **دمجًا بأسبقيّةٍ لا إحلالًا**:

```ts
values = { ...read(`package.nls.${locale}.json`), ...read(c).contents.package };
```
فيصير `package.nls.<locale>.json` تكميلًا مشروعًا للمفاتيح التي لا تغطّيها الحزمة، بدل
أن يموت صامتًا. وثانيًا: **حزمةُ لغةٍ مدمجةٌ تُحلّ في الإقلاع الأوّل** (لا بعد مسحِ
الإضافات) — تُسقط الحاجةَ إلى خبزِ الترجمة أصلًا.

**ما يسقط.** ‏`patch_extension_nls`، وجُلُّ `bake_nls_arabic` — ومعهما فخُّ الكاش
المعروف: مفتاحُ كاش الترجمة `md5(extId + version)` لا يتحرّك بإعادة البناء، فنضطرّ إلى
رفع نسخة `language-pack-ar` من بصمةِ محتوًى كي يُبطَل.

## م-١٠) اسمُ حزمة macOS يُحلّ لا يُفترَض

**عطبٌ صريحٌ في VSCodium.** ‏`build_cli.sh` و`prepare_assets.sh` يشتقّان مسارَ الحزمة من
`nameShort`، بينما يشتقّه مغلِّفُ vscode لـmacOS من **`nameLong`**. وهما في VSCodium نصٌّ
واحد فلا يظهر الفرقُ أبدًا؛ أمّا حين يختلفان (اسمٌ لاتينيٌّ قصير واسمٌ طويلٌ بلغةٍ أخرى)
فيبني المغلِّفُ `محراب.app` ويبحث السكربتُ عن `Mihrab.app`:

```
cp: .../VSCode-darwin-arm64/Mihrab.app/Contents/Resources/app/bin/mihrab-tunnel:
    No such file or directory
```

ويظهر **بعد ست عشرة دقيقة** من البناء، في آخر خطوة، بعد ترجمة CLI بـRust كاملةً.

**المقترحُ.** لا يُفرَض اسم — تُحلّ الحزمةُ الموجودة:

```sh
APP_PATH=$(ls -d "${OUT}"/*.app | head -1)
```
`ls -d` مصدرُ حقيقةٍ أصدقُ من أيّ اشتقاق، ويبقى صحيحًا لو غيّر المنبعُ قاعدةَ التسمية غدًا.

**ما يسقط.** ‏`patch_cli_macapp`. **جاهزٌ للرفع كما هو** — تصحيحُ سطرين، لا علاقةَ له
بمحراب، ويصيب أيَّ فرعٍ يُسمّي منتجَه بغير اللاتينيّة.

## م-١٣) إبرازُ المحارف الملتبِسة يُعادي العربيّة

ليست رُقعةَ مصدرٍ بل إعفاءً في `extensions/mihrab-shell/package.json` — ومكانُها هنا لأنّ
سببَها عطبٌ منبعيّ.

**الحالُ.** جدولُ `_common` في `vs/base/common/strings.ts` — **المدموجُ بلا شرطٍ في كلّ
محليّة** — يعدّ ‏٣٣ نقطةَ كودٍ عربيّةً «ملتبِسة»: الألف «ا» ⇐ `l`، والهاء «ه» ⇐ `o`،
والأرقامُ ٠١٥٧. وللمنبع استدلالُ سياقٍ يُعفي الكلمة، لكنّ شرطَه
**`!hasBasicASCIICharacters`** — أي أنّ **محرفَ ASCII واحدًا يُبطل الإعفاء كلَّه**.
ومعرّفاتُ ص تُكتب `نصاب_الفضة`، والشرطةُ السفليّة ASCII.

**القياس** (نفّذنا قاعدةَ المنبع حرفيًّا على مجموعاتٍ **مسمّاة**):

| المجموعة | النتيجة |
|---|---|
| نواة نهلة (‏١٧٤ ملفّ ص) | ‏٧٧٬٦٩٠ من ‏٦٠٧٬٠١٨ كلمة = **‏١٢٫٨٪** |
| أمثلة مستودع اللغة | ‏٥٩ من ‏٨٤٣ = ‏٧٫٠٪ |

أي مستطيلٌ أصفرُ حول واحدةٍ من كلّ ثماني كلماتٍ في شيفرةٍ عربيّةٍ سليمةٍ تمامًا. وليست
العربيّةُ وحدَها: المحليّةُ `ar` **غيرُ موجودةٍ في جدول المحليّات أصلًا**، فـ`allowedLocales`
عديمُ الأثر لكاتب العربيّة.

**المقترحُ المنبعيّ.** أحدُ ثلاثةٍ، مرتَّبةً بالأفضليّة:

1. **مدخلُ محليّةٍ `ar`** (وفارسيّة وأردو) في جدول `strings.ts`، فتخرج حروفُ الكتابة
   نفسِها من الالتباس لمن يكتب بها — وهي بنيةٌ قائمةٌ لا جديدة.
2. **استدلالُ السياق يقاس بالكتابة لا بـASCII** — ✅ **مكتوبٌ رقعةَ منبعٍ اليوم**:
   `patches/core/033-unicode-word-script-mixing.patch` ‏[AR-05]. حروفُ ASCII وحدَها
   تُعدّ خلطَ كتابتَين؛ والأرقامُ والشَرطةُ السفليّةُ وسائرُ الترقيم **غِراءُ معرّفاتٍ**
   محايدةُ الكتابة تستعملها كلُّ كتابة. وتعليقُ المنبع نفسُه يقول «لا تخلط الغريبَ
   بـASCII» — فالرقعةُ تجعل الشرطَ يقول ما يقصده تعليقُه.
3. **إعفاءٌ بالكتابة (‏script) لا بالمحرف**: ‏`"editor.unicodeHighlight.allowedScripts": ["arabic"]`.

> **بندٌ سُحِب — «الإصلاحُ السريع يُبطِل إعفاءَنا».** كان هنا عطبٌ رابعٌ مقترَحٌ للرفع:
> أنّ `excludeCharFromBeingHighlighted` يكتب في `ConfigurationTarget.USER` **عالميًّا
> وبلا `overrideIdentifier`** (وهذا صحيح، `unicodeHighlighter.ts`)، فتَغلب قيمةُ
> المستخدمِ افتراضَنا المحصورَ في `[sad]` **ذرّيًّا** فتعود المستطيلاتُ إلى ملفّات ص بنقرةٍ
> واحدةٍ في md. **والاستنتاجُ خطأٌ، نفَتْه قراءةُ المنبع:** الدمجُ بين المصادر وبين
> تجاوزات اللغة **عميقٌ لا ذرّيّ** — `ConfigurationModel.merge` و
> `createOverrideConfigurationModel` كلاهما يمرّ بـ`mergeContents`، وهي تنزل في كلّ قيمةٍ
> كائنًا. فمحرفُ المستخدم **يتّحد** بمحارفنا التسعةَ عشرَ ولا يحلّ محلَّها. والمفاتيحُ
> الذرّيّةُ حقًّا بوليانيّة، ولا مسارَ في الواجهة يكتب `nonBasicASCII: true`.
> أُبقي البندُ مسحوبًا مكتوبًا لا محذوفًا: بلا هذا السطر يُبعَث الاستنتاجُ نفسُه بعد شهرٍ،
> ويُرفَع إلى المنبع بلاغٌ عن عطبٍ غيرِ قائم. **ولا تُرفَع دعوى «ذرّيّة» بلا قراءةِ
> `mergeContents` أوّلًا.**

> **البندُ الرابعُ سُحِب مرّتين — والثانيةُ أهمُّ من الأولى.** بعد سحبِ دعوى «الذرّيّة»
> أعدنا صياغتَه: «قيمةُ المستخدم **العامّة** تغلب افتراضَنا المقصورَ على لغة». وهذا أيضًا
> **خطأ**، نفاه تشغيلُ شيفرة المنبع لا قراءتُها: `getConsolidatedConfigurationModel`
> (‏configurationModels.ts:990) يدمج المصادرَ كلَّها **ثمّ** يستدعي `.override(id)`،
> فمحتوى النطاق اللغويّ — أيًّا كان مصدرُه، ومنه افتراضُ إضافتنا — يُطبَّق **فوق** المتن.
> فقيمةُ مستخدمٍ عامّةٌ `nonBasicASCII: true` لا تُعيد الإطاراتِ إلى ملفّات ص؛ افتراضُنا
> يغلبها. والحالةُ الوحيدةُ التي تغلبنا هي قيمةٌ **بنطاقِ لغة** في إعدادات المستخدم أو
> المشروع (`"[sad]": {...}`) — وذلك ترتيبُ أسبقيّةٍ صحيحٌ ومقصود، لا عطبَ فيه.
>
> **فلا بندَ رابعًا يُرفَع.** ولا نرفع دعوى «محرّرُ الإعدادات لا يُظهر التظليل» لأنّا لم
> نتحقّق منها على واجهةٍ حيّة، وبندٌ غيرُ مُتحقَّقٍ منه هو ما أوقعنا في هذه الدورة مرّتين.
> وما عندنا اليومَ من أمرِ «أزِل الإطارات الصفراء» ليس التفافًا على عطبٍ منبعيّ، بل مخرجُ
> تعافٍ لمستخدمٍ ضبط إعدادًا لغويًّا ولا يعرف كيف يتراجع.

### الشقُّ الثاني مكتوبٌ — والقياسُ الذي حكم [AR-05]

**بلاغُ مستخدمٍ حقيقيٍّ فتحه**: «الألف حولها مربّع أصفر» في `مصدر_الحقيقة/مفردات.yaml`،
بينما `تصحيح.yaml` — نفسُ اللغة، نفسُ المجلّد — سليمٌ تمامًا. والفارقُ ليس اللغةَ ولا
الترميز: **الأوّلُ فيه معرّفاتٌ عربيّةٌ موصولةٌ بشَرطةٍ سفليّة** (`حقل_اسم`)، والثاني
معرّفاتُه لاتينيّة (`DBG_LEX_START`) ونثرُه العربيُّ بلا شَرطات.

وقاعدةُ المنبع نُفِّذت حرفيًّا، **والمرسومُ عُدَّ لا الخام**: `includeStrings` افتراضُه
‏`true` و`includeComments` افتراضُه `inUntrustedWorkspace` (‏`editorOptions.ts:4386-4387`)،
فالمخفيُّ في مساحةٍ موثوقة هو التعليقاتُ وحدَها.

| | مفردات.yaml (مرسوم) | كلُّ ‎.yaml‎ | كلُّ ‎.md‎ |
|---|---|---|---|
| اليوم | **‎622‎** | ‎1567‎ | ‎3068‎ |
| بإعفاء الشَرطة وحدَها | ‎0‎ | ‎335‎ | ‎846‎ |
| **بالرقعة (حروفُ ASCII)** | **‎0‎** | **‎7‎** | **‎654‎** |

**وصفرُ حمايةٍ تسقط** — قِيس على كلٍّ منها: `exampاe` · `contro١` · `pаssword` (سيريليّة)
· `faiا` · `pcb_ديناميّ` · `صادx` تبقى مُشخَّصةً كلُّها، لأنّ الكلمةَ التي تخلط كتابتَين
حقًّا فيها **حرفُ** ASCII لا رقمٌ ولا شَرطة.

**والبديلُ رُفض بالقراءة لا بالذوق**: رفعُ `allowedCharacters` إلى جذر الإعدادات كان
يُسقِط `ا`↦`l` و`ه`↦`o` في `.js` و`.py` وملفّاتِ سير العمل، لأنّ الإعفاءَ بالاسم يعود
‏`None` **قبل** الملتبِس والخفيّ و`nonBasicASCII` معًا. ويمنعه توكيدٌ قائمٌ في حارس
‏AR-04 — **وأوّلُ فعلٍ في ذلك البديل كان سيكون حذفَ حارسٍ أحمر**، وهو تخضيرٌ لا هندسة.

**وما لا تُصلحه الرقعةُ — يُقال ولا يُدَّعى**: الأرقامُ العربيّةُ المفردةُ في النثر
(`٥٥` · `١٠`) تبقى مُشخَّصةً خارج `[sad]` — كلمةٌ كلُّها ملتبسٌ بلا حرفٍ غيرِ ملتبسٍ فيها،
فبندُ الهروب لا يطالها بأيّ صياغة. وكذلك المختلطُ حقًّا (`اكتب32` — عربيٌّ وأرقامُ ASCII
ملتصقة) يبقى مُشخَّصًا: الرقمُ محايدٌ في **الوجود** لا في **الالتصاق**، ولم نوسّع الإعفاءَ
إليه لأنّ `contro١` يقع في الاتّجاه المعاكس بالبنية نفسِها. والبندان ‎1‎ و‎3‎ من المقترح
(مدخلُ محليّةٍ `ar` · إعفاءٌ بالكتابة) يبقيان قائمَين ويُسقِطان هذين معًا.

**ما يسقط.** إعفاءُ التسعةَ عشرَ محرفًا في `[sad]`، والحارسُ الساكنُ الذي يشتقّه من جدول
المنبع كي لا يبيت. ويبقى — بحيثيّةٍ أخرى لا علاقةَ لها بالمقترح — إطفاءُ `nonBasicASCII`
في `[markdown]` و`[plaintext]`: افتراضُه `inUntrustedWorkspace` وأيُّ مشروعٍ مُنزَّلٍ غيرُ
موثوقٍ ابتداءً، فيغرق README عربيٌّ كلُّه بالمستطيلات. ونحن **لم نُطفئ**
`ambiguousCharacters` ولا `invisibleCharacters` في أيّ نطاق، ولم نُعفِ محرفًا بالاسم خارج
ص: `shouldHighlightNonBasicASCII` يفحص `allowedCodePoints` **أوّلًا فيعود `None`** قبل
الملتبِس والخفيّ معًا، فالإعفاءُ بالاسم إسقاطُ حمايةٍ كامل — مقصودٌ ومقيسٌ في ص، بلا
مقابلٍ خارجَها. وهذا ما نطلب من المنبع تعميمَه: إعفاءٌ واعٍ بالكتابة، لا إسقاطَ حماية.

## م-١٥) تطبيعُ البحث للكتابة العربيّة

**الحالُ في المنبع.** كلُّ مطابقةٍ نصّيّةٍ في VS Code — ‏`filters.ts` (الإكمال والقوائم)،
‏`fuzzyScorer.ts` (‏«انتقل إلى ملفّ» و«انتقل إلى رمز»)، وبحثُ الملفّات — تقارن نقاطَ الكود
بعد خفضِ الحالة لا غير. وخفضُ الحالة مفهومٌ **لاتينيٌّ محض**: لا نظيرَ له في العربيّة،
ولا يعالج شيئًا ممّا يتبادله كاتبُها فعلًا.

**ما يكسره ذلك — يوميًّا لا نادرًا.**

| ما يكتبه الباحث | ما في الملفّ | النتيجة اليوم |
|---|---|---|
| `احمد` | `أحمد` | لا نتيجة (همزةُ قطعٍ مقابل ألفٍ) |
| `مكتبه` | `مكتبة` | لا نتيجة (تاءٌ مربوطةٌ مقابل هاء) |
| `علي` | `على` | لا نتيجة (ياءٌ مقابل ألفٍ مقصورة) |
| `نصاب الفضة` | `نِصابُ الفِضَّة` | لا نتيجة (التشكيلُ يُكتَب مرّةً ولا يُعاد) |
| `12` | `١٢` | لا نتيجة (رقمان لعددٍ واحد) |

والأثرُ ليس «نتيجةً ناقصة» بل **استنتاجٌ خاطئٌ عن الأداة**: الباحثُ يعرف أنّ الدالّةَ
موجودة، فلا يجدها، فيحكم بأنّ البحثَ معطوب. وهذا يصيب كلَّ من يكتب العربيّة في VS Code،
لا مستخدمي محرابٍ وحدَهم — والقاعدةُ نفسُها تسري على الفارسيّة والأردو.

**المقترحُ المنبعيّ.** إعدادٌ واحدٌ افتراضُه مشتقٌّ من لغة الواجهة:
‏`"search.arabicNormalization": true|false`، ويطبَّق في **موضعٍ واحد**: دالّةُ تهيئةِ
النصّ المشتركةِ التي تسبق المطابقةَ في `filters.ts` و`fuzzyScorer.ts` معًا. والتطبيعُ
المقترَحُ هو ما يفعله محرابٌ اليومَ في طبقته الأولى (وحدةُ `arabic-normalize.js`): تجريدُ
التشكيل والتطويل وعلاماتِ الاتّجاه، وتوحيدُ عائلة الألف والتاء المربوطة والألف المقصورة
وحاملَي الهمزة، وردُّ الأرقام الهنديّة إلى اللاتينيّة.

**ما يسقط عندنا.** لا رقعة — فليس عندنا رقعةٌ هنا أصلًا. ما يسقط **حدُّ** حلِّنا: اليومَ
نطبّع ما نملكه (إكمالُ ص عبر `filterText` ثنائيّ الرسم، ومعجمُ الإعدادات)، ويبقى بحثُ
الملفّات ولوحةُ الأوامر العامّةُ خارجَ متناولنا لأنّهما يعيشان في المنبع. ونحن **لا نرقّعهما**
عمدًا: مطابقةُ النصّ مسارٌ ساخنٌ في كلّ نقرة، ورقعةٌ فيه دَينٌ ثقيلٌ في أشدّ المواضع
انجرافًا.

### الشقُّ الثاني — **حدودُ الكلمة في المطابقة الضبابيّة** (مقيسٌ لا مُفترَض)

هذا شقٌّ منفصلٌ عن التطبيع، وأثرُه أشدّ: لا يُضعِف الترتيبَ بل **يُسقِط النتيجةَ إطلاقًا**.

**الحالُ في المنبع.** `editor.suggest.matchOnWordStartOnly` افتراضُه `true`
(`editorOptions.ts:5112`)، فيمرَّر `firstMatchCanBeWeak: false` إلى
`fuzzyScoreGracefulAggressive` (`suggestModel.ts:611`). ومعناه أنّ المطابقةَ يجب أن تبدأ عند
**حدّ كلمة** — وحدودُ الكلمة عند المنبع لاتينيّةٌ صرفة: `camelCase`، وحرفٌ كبيرٌ بعد صغير،
وفواصلُ ASCII. ولا شيءَ منها في معرّفات ص.

**القياس** (‏`tests/dx/completion_rank.mjs` — يصرّف `filters.ts` من العقدة المثبَّتة ويستدعي
المُطابِقَ نفسَه بخياراته المشحونة، على ‎٢٠‎ معرّفًا عربيًّا و‎٨‎ كتاباتٍ جزئيّة):

| المكتوب | المطلوب | النتيجة |
|---|---|---|
| «نصاب» | `نصاب_الفضة` | ✅ يظهر (بدايةُ المعرّف) |
| «طباعة» | `طباعة_التقرير` | ✅ يظهر (بدايةُ المعرّف) |
| **«فضة»** | `نصاب_الفضة` | ❌ **لا يظهر إطلاقًا** |
| **«زكاة»** | `حساب_الزكاة` | ❌ **لا يظهر إطلاقًا** |
| **«مرور»** | `كلمة_المرور` | ❌ **لا يظهر إطلاقًا** |
| **«تقرير»** | `طباعة_التقرير` | ❌ **لا يظهر إطلاقًا** |

‏**‎٤‎ من ‎٨‎.** والكاتبُ العربيُّ يكتب من وسط المعرّف كما يكتب اللاتينيُّ `Btn` بحثًا عن
`SubmitButton` — الفرقُ أنّ الثاني يجد والأوّلَ لا يجد.

#### والقياسُ الثاني نقض تشخيصَنا الأوّل

كان الحكمُ أنّ **الفاصلةَ** لاتينيّةُ الأثر: «الشرطةُ السفليّةُ لا تُعَدّ بدايةَ كلمةٍ في
العربيّة». وهو خطأ. قِيس بعده حرفًا حرفًا، فإذا كتابةُ «الفضة» **تُظهِر** `نصاب_الفضة`
اليوم بلا رقعة (‏`_doScore` يمنح ما بعد الفاصلة درجةَ ٥ ولا ينظر إلى الكتابة). فالفاصلةُ
تعمل، والساقطُ شيءٌ آخر:

**أداةُ التعريف.** المقطعُ بعد الشرطة يبدأ بـ«ال»، والعربيُّ يكتب «فضة» لا «الفضة» — كما
يكتب اللاتينيُّ `Btn` لا `SubmitButton`. فأداةُ التعريف في كتابةٍ **بلا حالةِ أحرف** هي
نظيرُ الحرف الكبير تمامًا: العلامةُ التي تقول «هنا تبدأ الكلمةُ الثانية». والمنبعُ يعرف
العلامةَ اللاتينيّة ولا يعرف نظيرَها.

**المقترحُ المنبعيّ.** حدٌّ رابعٌ في `_doScore` إلى جانب الثلاثة القائمة (سابقةُ الكلمة،
الحرفُ الكبير، ما بعد الفاصلة): **ما بعد أداة التعريف حين تكون هي نفسُها في أوّل مقطع** —
فلا تُعَدّ «ال» في آخر «مالك» أداةً. دالّةٌ واحدةٌ من سبعة أسطر، ومكالمتان.

**مكتوبٌ ومقيسٌ (2026-08-06).** `patches/core/020-nonlatin-word-start.patch`: تعديلٌ
إنجليزيٌّ لا يذكر محرابًا، مع **اختبارِ وحدةٍ منبعيٍّ** في `filters.test.ts`. الحصيلة:

| | قبل | بعد |
|---|---|---|
| كتاباتٌ لا تُظهِر مقصودَها | **٤ من ٨** (فضة، زكاة، مرور، تقرير) | **صفر** |
| في الصدارة | ٤/٨ | **٧/٨** (والثامنةُ ثانيةٌ من اثنتين) |
| اختباراتُ `filters.test.ts` المنبعيّة | ٤٠/٤٠ | **٤١/٤١** (بالجديد) |

ولا أثرَ على اللاتينيّة بحكم البناء: الشرطُ يقرأ محرفَين عربيَّين بعينهما. قِيس ضابطًا:
`foo`→`bar_foo` و`Btn`→`SubmitButton` و`oo`→`bar_foo` (ساقطةٌ عمدًا) — الدرجاتُ نفسُها
حرفيًّا قبلَ الرقعة وبعدَها.

**والحارسُ يقيس الأثرَ لا الوجود**: `tests/dx/completion_rank.mjs` يصرّف المُطابِقَ مرّتين —
عاريًا وبرقعتنا — فيُفشِل إن سقطت كتابةٌ، **ويقول إن لم تعد الرقعةُ تشتري شيئًا** (فتُحذَف
بدل أن تبقى دَينًا بلا ثمن). ولا يقرأ الشجرةَ كما هي: شجرةٌ بعد بناءٍ تحمل الرقعةَ فيصير
القياسُ إخبارًا عن آخر بناءٍ لا عمّا نشحن.

**سابقةٌ قبل الرفع.** لم يُبحَث بعدُ عن بلاغٍ سابقٍ في `microsoft/vscode` عن تطبيع البحث
ولا عن حدود الكلمة غير اللاتينيّة. **لم نبحث، ونقولها كما هي** — والبحثُ شرطُ الرفع لا تحسينُه.
فالرقعةُ تُشحَن في محرابٍ اليومَ ولم تُرفَع بعد.

## م-١٦) الأسطحُ المُصيَّرةُ في webview لا ترث اتّجاهَ مضيفها

**الحالُ في المنبع.** يبني `GettingStartedDetailsRenderer.renderMarkdown` مستندَ HTML كاملًا
نصًّا ويُحمَّل في webview. ذلك المستندُ يخرج بـ`<html>` عاريةً: لا `dir` ولا `lang`. فمهما
كان اتّجاهُ القشرة المضيفة، يرتدّ لوحُ شرحِ الجولة إلى `ltr` — وهو حدُّ مستندٍ لا حدُّ
تنسيق، فلا ورقةَ أنماطٍ في القشرة تعبره.

**الأثرُ المقيس** (‏CDP على الحزمة المشحونة، لا استنتاجًا من المصدر):
`documentElement.getAttribute('dir') === null` و`getComputedStyle(p).direction === 'ltr'`
على فقرةٍ عربيّةٍ خالصة. وبالعين: النقطةُ الختاميّة تقفز إلى يسار السطر
(«‎.الكتابة إلى العربيّة»)، وأعمدةُ الجداول تبدأ من اليسار، والقوائمُ تُحاذى يسارًا —
داخل لوحٍ كلُّ ما حوله يمينيّ.

**ولا مَخرجَ من طبقةٍ أدنى.** جُرِّبت الثلاث: محتوى الجولة `.md` لنا، لكنّ
`readAndCacheStepMarkdown` يمرّره على مطهِّرٍ قائمتُه البيضاء `allowedMarkdownHtmlAttributes`
ولا `dir` فيها، فيُنزَع `<div dir="rtl">` صامتًا؛ وورقةُ أنماطنا لا تعبر حدَّ الـwebview؛
ولا خيارَ إعدادٍ لاتّجاه اللوح.

**المقترح.** سطران في مُولِّد القالب — يُشتقّ الاتّجاهُ من مستند المضيف لا يُثبَّت:

```ts
const dir = document.documentElement.getAttribute('dir') || 'ltr';
const lang = document.documentElement.getAttribute('lang') || 'en';
return `<!DOCTYPE html>\n<html dir="${dir}" lang="${lang}">…`;
```

ومعهما `padding-right: 32px` ⇐ `padding-inline-end` في أنماط القالب: الحشوةُ فجوةٌ إلى
حافّة النافذة، وموضعُ اللوح ينقلب مع الاتّجاه بينما الحشوةُ الفيزيائيّة لا تنقلب.
مطابقٌ بايتًا في LTR.

**نطاقٌ أوسعُ من جولتنا.** العطبُ في المُولِّد لا في محتوانا، فيصيب كلَّ حزمةِ لغةٍ RTL
(عربيّة · عبريّة · فارسيّة) في كلّ جولةِ ترحيبٍ يشحنها المنبعُ أو أيُّ امتداد. وهو مستقلٌّ
عن م-١: يبقى قائمًا حتّى بعد أن ترثَ القشرةُ كلُّها اتّجاهًا منطقيًّا.

**سابقةٌ قبل الرفع.** لم يُبحَث بعدُ عن بلاغٍ سابقٍ في `microsoft/vscode` عن اتّجاه
مستندات الـwebview المولَّدة داخليًّا. **لم نبحث، ونقولها كما هي.**

### شاهدٌ ثانٍ — ولماذا **لا** يُعمَّم الاتّجاه ‏[WV-01]

> ### ‏⛔ حالُ هذا الشاهد: **البندُ أُغلِق سلبًا — والشقُّ (أ) أدناه مسحوبٌ لا مؤجَّل**
>
> ما دون هذا الإطار مكتوبٌ كما كُتب أوّلَ مرّة، ويبقى لأنّ حجّتَه عن الشقّ الأوّل صحيحة.
> أمّا **الشقُّ (أ)** — إعلانُ `lang` حين لا يعلنه كاتبُ المحتوى — فقد **سقط بالقراءة
> بعده**، ولا يُرفَع مقترحًا منبعيًّا في صيغته تلك:
>
> **(١) فارغٌ عندنا**: لوحاتُ محرابٍ الخمسُ تُعلن `<html lang="ar" dir="rtl">` في مصدرها
> (`help-panel.js:144` · `output-panel.js:181` · `print-export.js:207` ·
> `import-settings.js:291` · `mihrab-nebras/chat.js:79`)، ولوحُ الجولة مرقوعٌ سلفًا. صفرُ
> إطلاقاتٍ على شيفرتنا.
>
> **(٢) وضارٌّ حيث يُطلَق**: المتاحُ داخلَ ذلك السياق لغةُ **الواجهة**، ومحتوى اللوحات
> العاريةِ ليس بلغتها (‏README كاتبٍ ثالثٍ · ملاحظاتُ إصدارٍ إنجليزيّةٌ دائمًا · موقعٌ
> خارجيّ). فيتحوّل «لا إعلان» إلى **إعلانٍ كاذب**: القارئُ الذي لا يجد `lang` يرتدّ إلى
> صوت المستخدم، والذي يجد `lang="ar"` على إنجليزيّةٍ **يُلزَم** بالنطق العربيّ — إخفاقُ
> ‏WCAG 3.1.1 لا إصلاحُه.
>
> **(٣) وغيرُ منفَّذٍ في موضعه**: لغةُ المضيف غيرُ معروفةٍ داخل `toContentHtml` (‏عزلُ
> الأصل — مُقاسٌ في `walkthrough_dir.live.mjs`)، فحملُها يوجب تعديلَ `webviewMessages.d.ts`
> **وجسمِ البرنامج المضمَّن** في `pre/index.html` ⇒ إبطالُ بصمة CSP ⇒ إطفاءُ **كلِّ**
> اللوحات صامتةً.
>
> **والقاعدة**: الإعلانُ عند **بانِي المحتوى** الذي يعرف لغتَه، لا في نواةِ الـwebview.
>
> **والشقُّ (ب)** (`WebviewOptions.inheritDirection`) يبقى مقترحًا قائمًا — **لكنّ موضعَه
> ليس `index.html`**: تنفيذُه هناك يرث كمينَ البصمة نفسَه، وموضعُه الصحيح
> `webviewElement.ts` (‏`doUpdateContent` ‏`:673-692`) الذي يعمل في القشرة ويقرأ
> `document.documentElement` مباشرةً.
>
> **وما خرج من البند حارسٌ لا رقعة**: `check_webview_csp` في `tests/apply/check_anchors.py`
> — يقارن بصمةَ السطر ‎8‎ ببرنامجِ الملفّ المضمَّن (‏sha256 بعد تسوية LF)، فأيُّ رقعةٍ
> مستقبليّةٍ تلمس ذلك البرنامجَ تحمرّ فورًا بدلَ أن تُطفئ اللوحاتِ صامتةً.

قُرِئ إطارُ الاستضافة الذي يحمل **كلَّ** webview في المحرّر
(‏`webview/browser/pre/index.html`)، وفيه شاهدان مختلفان لا شاهدٌ واحد:

**(‏١) `<html lang="en">` مثبَّتٌ في السطر ‎2‎ — ولا يستحقّ رقعة.** كان المقترحُ عندنا أن
نضبط `lang`/`dir` عليه بسابقة `patch_walkthrough_dir.py`. وقراءةُ الملفّ **ردّت
المقترح**: جسمُ ذلك المستند لا يحمل نصًّا أصلًا —

```html
<body style="margin: 0; overflow: hidden; …" role="document">
	<script async type="module">
```

لا شيءَ فيه إلّا `<iframe>` والبرنامج، و`dir` **لا تعبر حدَّ مستندِ الإطار** إلى مستند
المحتوى. فرقعةٌ هناك تجتاز الحرّاسَ ولا تغيّر بكسلًا واحدًا — وهي بعينها **القاعدةُ
الميّتة** التي تجنّبناها في ‏SC-01 حين قِسنا جدوى الحقن قبل كتابته. فلم تُكتَب.

**(‏٢) والموضعُ الحيُّ `toContentHtml` (‏`:841-901`)** — وهي الدالّةُ التي تبني مستندَ
**كلِّ** webview قبل تحميله، وتُعدِّله فعلًا اليوم: تضبط `role="document"` على الجسم إن
غاب، وتحقن الأنماطَ الافتراضيّة، وتستدعي `applyStyles`. فهي المكانُ الطبيعيُّ لأيّ
افتراضٍ مستنديّ.

**ومع ذلك: `dir` لا تُورَّث هناك — وهذا حكمٌ لا تردُّد.** محتوى ذلك المستند **يكتبه
كاتبُ امتدادٍ ثالثٍ لا نعرفه**، وأكثرُه إنجليزيٌّ مصمَّمٌ لـLTR. فوراثةُ `rtl` من القشرة
تقلب **كلَّ لوحةِ امتدادٍ إنجليزيّةٍ** في المحرّر — انحدارٌ يصيب آلافَ الامتدادات، لا
إصلاح. والفرقُ عن م-١٦ فرقٌ في المِلكيّة لا في الآليّة: هناك المستندُ **من توليد VS Code
نفسِه ومحتواه معروفُ اللغة**، وهنا المحتوى محتوى غيرِنا.

**فالمقترحُ يقتصر على شقّين آمنَين:**

```ts
// (أ) اللغة: تُشتقّ من المضيف حين لا يعلنها كاتبُ المحتوى — لا تُثبَّت "en"
if (!newDocument.documentElement.hasAttribute('lang')) {
  newDocument.documentElement.setAttribute('lang', hostLang);
}
// (ب) والاتّجاه بإقرارٍ صريحٍ من كاتب اللوحة لا بالوراثة
//     WebviewOptions.inheritDirection?: boolean  (افتراضُه false ⇒ صفرُ انحدار)
```

الشقُّ (أ) **إصلاحُ وصولٍ خالص**: قارئُ الشاشة ينطق العربيّةَ نطقًا إنجليزيًّا حين تُعلَن
اللغةُ `en` كذبًا، وهو يصيب كلَّ لغةٍ غيرِ إنجليزيّة. والشقُّ (ب) **يفتح البابَ ولا
يكسر أحدًا**.

**وهذا لم يُقَس حيًّا.** الحكمُ مبنيٌّ على قراءة `index.html` في الشجرة المثبَّتة؛ ولم
نرصد بـCDP ما يُصيَّر داخلَ لوحةِ امتدادٍ ثالثٍ في محرابٍ فعلًا. **يُقال ولا يُدَّعى.**

## م-١٧) قائمةُ سماحِ صندوقِ رسالة الالتزام مغلقة

> ### ‏⬛ حالُ هذا المقترح: **مُنفَّذٌ رقعتَي نواةٍ ‎030‎ و‎032‎ — وموضعُه ليس الذي كُتب أدناه**

> راجعت **سالي** البندَ فقالت إنّه أشدُّ الأربعة إيجاعًا يوميًّا: رسالةُ الالتزام **أطولُ
> نصٍّ عربيٍّ متّصلٍ يكتبه المستخدمُ في المحرِّر أصلًا** (الشيفرةُ معرِّفاتٌ قصيرة)، ويقع
> من ثلاثِ مرّاتٍ إلى عشرٍ في اليوم — فينتقل من محرِّرٍ عربيٍّ سليمٍ إلى صندوقٍ إنجليزيٍّ
> **في الشاشة نفسِها**.
>
> **ثمّ صحّحت موضعَ الإصلاح**: هذا القسمُ يقترح توسيعَ القائمة في `scmInput.ts` وحدَه.
> وقراءةُ `simpleEditorOptions.ts:20` تُظهِر أنّ `getSimpleEditorOptions` **يستقبل خدمةَ
> الإعدادات سلفًا ويقرأ منها ستّةَ مفاتيح** — فإضافةُ `textDirection` و`fontLigatures`
> هناك سطران بالصيغة القائمة نفسِها، ويعبران دفعةً واحدةً إلى **أحدَ عشرَ مستهلكًا**:
> رسالةُ الالتزام · حقلُ وحدة التصحيح · شرطُ نقطة التوقّف · الدردشة · `suggestEnabledInput`
> وغيرُها. أوسعُ أثرًا وأقلُّ مساسًا بالمنبع.
>
> وضُمَّ إليه شقٌّ ثانٍ: `_getEditorLineHeight` كان `Math.round(fontSize * 1.5)` **بلا
> قراءةِ `editor.lineHeight` إطلاقًا** — نسبةٌ لاتينيّة، ومدى حبر Kawkab Mono العربيُّ
> ‎1.88em‎، فتُقصّ الفتحةُ والكسرةُ في ذلك السطح بعينه.
>
> **وسطحان لم يذكرهما بندٌ من الثلاثة عشر** يُغلقان معه: صندوقُ شرط نقطة التوقّف
> (`breakpointWidget.ts`) وحقلُ إدخال وحدة التصحيح (`repl.ts`) — كلاهما سطحُ **كتابةٍ**
> عربيٍّ بلا اتّجاهٍ وبأحرفٍ مفكَّكة، و`DG-01` أغلق **خطَّ** وحدة التصحيح ولم يمسّ حقلَها.
>
> **ثمّ شقٌّ ثالثٌ في رقعةٍ ثانية: التجدُّدُ الحيّ.** ما فوقَه يصل الصندوقَ **عند الإنشاء**؛
> ومُرشِّحُ تغيّر الإعدادات (‏`scmInput.ts:259-270`) لا يذكر أيًّا من الثلاثة. والشقُّ الحاملُ
> ليس المرشِّح: `onDidChangeEditorOptions` لا يدفع إلّا حمولةَ `getEditorOptions()`
> (‏`:749-751`)، و`textDirection` و`fontLigatures` **ليسا فيها أصلًا** — فإضافةُ المفاتيح
> إلى المرشِّح وحدَه رقعةٌ تبدو مغلِقةً وهي فارغةٌ في اثنين من ثلاثة. و`editor.lineHeight`
> كان **حيًّا بالوكالة**: `_getEditorLineHeight` يقرأه في كلّ استدعاء ولا يُستدعى إلّا حين
> يتغيّر مفتاحٌ آخرُ مذكورٌ في المرشِّح — وتجدُّدٌ متقطّعٌ يُقرأ «الإعدادُ يعمل أحيانًا»، وهو
> أسوأُ من خمودٍ صريح.
>
> **ولماذا هذا خللٌ لا تأخير.** الصندوقُ يعمّر عمرَ الجلسة: `RowCache` يُعيد الصفوفَ المُفرَجَ
> عنها إلى مخبأٍ ولا يُتلِفها (‏`rowCache.ts:50-56`)، و`disposeTemplate` لا يجري إلّا بإتلاف
> الشجرة؛ وتبديلُ المستودع يُسنِد `input` على الودجة نفسِها، والطيُّ ينزع الجسمَ ولا يُعيد
> تصييره (‏`paneview.ts:161-193`). فمن غيّر إعدادَه ثمّ أظهر مستودعًا ثانيًا — يحتاج صفًّا
> جديدًا والمخبأُ فارغ — رأى **صندوقَين في عرضٍ واحدٍ يختلفان في الاتّجاه**.
>
> والرقعتان: `patches/core/030-simple-editor-rtl-input.patch` و
> `patches/core/032-scm-input-live-options.patch`. تسقطان يومَ يُدمَج المقترح.
>
> **وحدّان يُعلَنان ولا يُدَّعى إغلاقُهما**: (١) القراءةُ هنا وفي `getSimpleEditorOptions`
> بلا `overrideIdentifier`، فكتلةُ `[scminput]` لهذه المفاتيح تبقى ميّتة — بخلاف `rulers`
> و`wordWrap` اللذَين يُقرآن بالنطاق. (٢) التجدُّدُ الحيُّ **لصندوق الالتزام وحدَه**: بقيّةُ
> المحرّرات البسيطة التي بلغتها ‎030‎ تبني خياراتِها عند إنشائها ولا ترصد شيئًا.

**الحالُ في المنبع.** صندوقُ رسالة الالتزام في جزء المصادر ليس حقلَ إدخال بل **محرّرَ
Monaco كاملًا**: `scmInput.ts:619` ينشئ `CodeEditorWidget`، و`:613` يمرّر
`isSimpleWidget: true`. و«الودجةُ البسيطة» **لا تقرأ خدمةَ الإعدادات إطلاقًا** —
`editorConfiguration.ts:73-88` تبني خياراتِها من كائنٍ مُمرَّرٍ بلا حقن
`IConfigurationService`. ولذلك يُعيد `SCMInputWidget` قراءةَ ما يريده **بيده**، في قائمةٍ
مغلقةٍ صريحةٍ عند `scmInput.ts:298-311`:

```ts
return { ...this._getEditorLanguageConfiguration(), accessibilitySupport,
  cursorBlinking, cursorStyle, cursorWidth, fontFamily, fontSize,
  lineHeight, emptySelectionClipboard, roundedSelection, wordSegmenterLocales };
```

و`_getEditorLanguageConfiguration()` (‏`:331-341`) لا يقرأ بنطاق `scminput` إلّا مفتاحَين:
`editor.rulers` و`editor.wordWrap`.

**الأثر.** المستخدمُ العربيُّ يكتب في هذا الصندوق **أطولَ نصٍّ عربيٍّ متّصلٍ في يومه** —
رسالةَ الالتزام — وهو السطحُ الوحيدُ الذي لا يبلغه شيءٌ ممّا ضبطه:

| ما ضُبِط | ماذا يصل الصندوق فعلًا |
|---|---|
| `editor.textDirection: rtl` | **لا شيء** — المفتاحُ ليس في القائمة ولا في مُرشِّح التغيّر (‏`:255-269`) |
| `editor.fontLigatures: true` | ليس في القائمة ⇒ افتراضُ المنبع `EditorFontLigatures.OFF`. **وفي العربيّة هذا ليس فقدَ زخرفة بل تفكُّكَ الكلمة** إلى حروفٍ منفصلة |
| `editor.lineHeight` | `scmInput.ts:343-345`: `Math.round(fontSize * 1.5)` — معامِلٌ **مثبَّتٌ في الشيفرة**، يقتطع الحبرَ العلويَّ لأيّ وجهٍ عربيّ (قِسنا أرضيّةَ Kawkab Mono ‎1.88em‎) |

والوجهُ والحجمُ وحدَهما لهما مَخرجٌ من الطبقة الأولى (`scm.inputFontFamily: "editor"` و
`scm.inputFontSize`) — وقد ضبطناهما. **والثلاثةُ الباقيةُ لا مخرجَ لها دون المنبع**، لأنّ
الاتّجاهَ قرارُ تخطيطٍ داخل Monaco لا خاصّيّةُ نمط، والأشكالَ السياقيّةَ خيارُ محرّرٍ لا
ورقةُ أنماط.

**المقترح.** توسيعُ القائمة المغلقة بالشكل القائم نفسِه الذي تُقرأ به `rulers`/`wordWrap`
بنطاق `scminput` — لا آليّةٌ جديدة:

```ts
const textDirection = this.configurationService.getValue<'ltr' | 'rtl'>('editor.textDirection');
const fontLigatures = this.configurationService.getValue<boolean | string>('editor.fontLigatures');
// ولارتفاع السطر: احترامُ editor.lineHeight متى ضُبِط، والمعامِلُ ‎1.5‎ افتراضًا لا حكمًا
```

ويُضاف `textDirection` و`fontLigatures` و`lineHeight` إلى مُرشِّح التغيّر (‏`:255-269`) كي
يسري التبديلُ بلا إعادة تشغيل.

**نطاقُه أوسعُ من محراب.** العطبُ يصيب **كلَّ لغةٍ من اليمين** في VS Code الرسميّ — عربيّةً
وعبريّةً وفارسيّةً وأرديّة — ولو لم يوجد محرابٌ أصلًا. وهو إنجليزيُّ الصياغة، لا يذكر
محرابًا، ومن صنف `010` و`020` لا من صنف رُقَع الهويّة.

**سابقةٌ قبل الرفع.** **لم يُبحَث** بعدُ عن بلاغٍ سابقٍ في `microsoft/vscode` عن إعدادات
صندوق SCM. ونقولها كما هي.

> ### ‏⬛ ما شُحن **أضيقُ ممّا كُتب هنا** — والفرقُ يُسمّى
>
> راجعت **سالي** الرقعةَ المشحونة `030` مقابل هذا القسم، فوجدت شقًّا من المقترح
> **لم يُنفَّذ**: الفقرةُ أعلاه تطلب إضافةَ المفاتيح إلى **مُرشِّح التغيّر** كي يسري
> التبديلُ بلا إعادة تشغيل — والرقعةُ لم تفعل. ‏`scmInput.ts:258-270` لا يذكر
> `editor.textDirection` ولا `editor.lineHeight` ولا `editor.fontLigatures`، وحمولةُ
> `updateOptions` (‏`:298-311`) لا تحويها كذلك.
>
> **فالقيمُ تُلتقَط عند إنشاء الصندوق ولا تتجدّد حيًّا.** من غيّر اتّجاهَه أو ارتفاعَ
> سطره وهو يعمل يرى المحرّرَ يتبعه ولا يرى الصندوقَ — حتّى إعادة التحميل. وهو **أخفُّ
> بكثيرٍ** من العطب الأصليّ (لم يكن يصله شيءٌ إطلاقًا)، ولذلك لم يُوقِف الشحن.
>
> ‏**ويُقال ولا يُدَّعى**: البندُ `SC-01` مغلقٌ في الاتّجاه والوجه والحجم والأشكال
> وارتفاعِ السطر، **ومفتوحٌ في التجدّد الحيّ**. وهذا هو ما يستحقّ سطرَين في الرفع.

**والمقترحُ حين يُرفَع يُرفَع بموضعه المصحَّح** — `simpleEditorOptions.ts` لا
`scmInput.ts` وحدَه — كما في الرقعة المشحونة. والصيغةُ أعلاه محفوظةٌ لأنّها **تاريخُ
الاستدلال**: كُتبت على قراءةٍ أضيق، فصُحِّحت بقراءةٍ أوسع.

## م-١٨) علامةُ المساواة مُلصَقةٌ باسم المتغيّر في لوحات التنقيح

**الحالُ في المنبع.** `debugExpressionRenderer.ts:96-108`:

```ts
let text = variable.name;
if (variable.value && typeof variable.name === 'string') {
  if (variable.type && displayType) { text += ': '; data.type.textContent = variable.type + ' ='; }
  else { text += ' ='; }
}
data.label.set(text, highlights.name, …);
```

أي أنّ علامةَ المساواة **تُلصَق بالاسم في سلسلةٍ واحدة**، فتصير لمتغيّرٍ عربيّ
`"المجموع ="`. و«‎=‎» محرفٌ محايد (‏ON) لا حرفٌ قويّ، فيتبع اتّجاهَ الفقرة: في لوحةٍ عربيّةٍ
يهاجر إلى الطرف المقابل فيُقرأ `"= المجموع"`. والقيمةُ في `span.value` **شقيقٍ منفصلٍ**
بتخطيط flex، فلا عزلَ بين المقطعين. و`watchExpressionsView.ts:314-345` يكرّر الصياغةَ نفسَها.

وبحثٌ قاطعٌ في `workbench/contrib/debug/browser/` و`common/`: عن
`u2066|u2067|u2068|u2069|LRI|FSI|PDI|bidi` ⇒ **صفر**؛ وعن
`setAttribute('dir')|textDirection|dir="` ⇒ **صفر**؛ و`unicode-bidi` في أوراق أنماط
التنقيح ⇒ **صفر**. و`direction` الوحيدةُ في `media/repl.css:90` وتعليقُها يقول صراحةً
إنّها حيلةُ موضعِ نقاطٍ لا معالجةَ اتّجاه.

**المقترح.** فصلُ «‎=‎» عن الاسم إلى عنصرٍ ثالث في القالب (كما فُصلت القيمةُ أصلًا)، أو —
إن تعذّر تغييرُ البنية — لفُّ الاسم بـ`U+2068…U+2069` (‏FSI…PDI) عند بنائه.

**والعزلُ في النصّ لا في الورقة** — وهي القاعدةُ التي طبّقناها بأنفسنا في
`error-format.js`. والشكلُ نفسُه المطلوبُ في م-٤ (عزلُ عناوين الإعدادات) وم-١٣.

**لكنّ حُجّةَ «تبلغ `aria-label` والحافظة» — التي كانت مكتوبةً هنا — باطلةٌ في طرفَيها،
وحذفُها يُضعِف هذا البند عمدًا.** قُرِئ المسارانِ فوُجِدا لا يمرّان بهذه السلسلة:

- **قارئُ الشاشة لا يسمع «‎=‎» أصلًا**: ‏`variablesView.ts:664` و`watchExpressionsView.ts:490,494`
  يبنيان التسميةَ من `element.name` و`element.value` **مباشرةً** بقالبِ
  `"{0}, value {1}"` — لا تمرّ بـ`text` المُلصَقة إطلاقًا.
- **ولا حافظةَ من الصفّ**: ‏`list.css:14-17` يضع `user-select: none` على
  `.monaco-list.mouse-support` ⇒ لا تحديدَ نصٍّ ولا نسخَ منه؛ و`COPY_VALUE_ID` ينسخ
  **القيمةَ وحدَها**، و`title` وسيطٌ ثالثٌ منفصلٌ في `label.set(text, highlights, title)`.

فالحاصلُ أنّ هذا البندَ **بلا مستهلِكٍ متضرِّرٍ واحدٍ مُثبَت**: لا عينٌ ترى العطبَ
(القياسُ الحيُّ أدناه)، ولا أذنٌ تسمعه، ولا حافظةٌ تنقله. وهو **نظافةُ سلسلةٍ في
المنبع** لا إصلاحُ عطبٍ واقع. والإبقاءُ على حُجّةٍ باطلةٍ لتقويته **أحمرُ كاذب** —
بندٌ يبقى مفتوحًا بضررٍ لا يقع، فيُزاحم بندًا يقع ضررُه.

**حقٌّ يُقال في حجمه.** هذا البندُ **يشتري نظافةً في المنبع ولا يسدّ دَينًا عندنا**: لا
رقعةَ في محراب تسقط بقبوله. فأولويّتُه متوسّطةٌ لا عالية — والصدقُ في تسمية ذلك شرطُ قراءةِ
هذا الملفّ بعد ستّة أشهر.

**سابقةٌ قبل الرفع.** **لم يُبحَث.**

> ### ‏⬛ حكمٌ: **لا رقعةَ نواةٍ لهذا البند** — يبقى مقترحًا يُرفَع ويُنسى
>
> أُذن بتعديل المنبع، فراجعت **سالي** البندَ ورَدَّته بالحجّة المكتوبة في هذا القسم نفسِه:
> «يشتري نظافةً في المنبع ولا يسدّ دَينًا عندنا — لا رقعةَ في محراب تسقط بقبوله».
>
> والقياسُ الحيُّ أدناه يؤيّد: **العطبُ البصريُّ لا يقع**. المستخدمُ يرى `الشاهد = ١٢`
> مضبوطًا، في الصفّ العربيّ واللاتينيّ معًا.
>
> **وتصحيحٌ لاحق (إيميليا)**: كان مكتوبًا هنا «والضررُ محصورٌ في النسخ و`aria-label`».
> وذلك **باطلٌ في الطرفين** بالقراءة — راجع الفقرةَ أعلاه. فالحكمُ بالردّ يبقى،
> **وحجّتُه تقوى**: لا ضررَ محصورًا، بل لا ضررَ مُثبَتًا.
>
> والمستودعُ يعدّ **عددَ رُقَع النواة مقياسَ صحّةٍ يجب أن ينخفض**. فرقعةٌ هنا خسارةٌ
> صافيةٌ بالمقياس المُعلَن: تُضاف إلى العمود ولا يسقط بها شيء. وقد كُتب التعديلُ فعلًا في
> شجرة المنبع ثمّ **تُراجِع عنه** بعد هذه المراجعة — والذكرُ هنا كي لا يُعاد.

### ما فعله القياسُ الحيُّ بهذا المقترح — **ضيّقه ولم يُلغِه** ‏[DG-01]

كُتِب هذا البندُ على قراءة الشيفرة، ثمّ قِيس حيًّا (‏`tests/runtime/debug_panes.live.mjs`،
جلسةُ تنقيحٍ حقيقيّةٌ متوقّفةٌ على متغيّرات عربيّةٍ ولاتينيّةٍ في الملفّ نفسِه). والنتيجةُ
**نقضت نصفَ الدعوى وأكّدت نصفَها**:

| المقيس | النتيجة |
|---|---|
| موضعُ «‎=‎» فيزيائيًّا (صفٌّ عربيّ: `الشاهد =`) | **بين** الاسم والقيمة ✅ |
| موضعُها في الصفّ اللاتينيّ المجاور (`total =`) | **بين** الاسم والقيمة ✅ |
| عقدةُ النصّ المُصدَّرة | `"الشاهد ="` — **ملصَقةٌ بلا عزل** ❌ |

أي أنّ **العطبَ الهندسيَّ المتوقَّع لا يقع**: ‏`span.name` بندُ flex فيُكتَّل، فيصير فقرةً
bidi مستقلّةً يستقرّ فيها المحايدُ الذيليُّ على الحافّة المواجهة للقيمة أصلًا. وحقنُ
`unicode-bidi: plaintext` عليه قِيس فوجِد **يقلب القيمةَ المحسوبةَ ولا يزحزح بكسلًا**.

**فالعطبُ عطبُ سلسلةٍ لا عطبُ عرض.** و**لا مُحدِّدَ CSS يصل إلى جزءٍ من عقدة نصّ**
(‏`unicode-bidi` تعزل صندوقًا لا محرفًا)، فلا مخرجَ من الطبقة الثانية بحالٍ، والعلاجُ
الوحيدُ فصلُ العنصر أو `FSI…PDI` في المصدر — أي هذا المقترحُ بعينه. **لكنّ ذلك يُبقيه
مقترحًا لا يُصيّره عاجلًا**: كُتب هنا أوّلًا أنّ العقدةَ «تذهب إلى `aria-label` وإلى
نسخ» فيُقرأ كأنّ الضررَ واقعٌ في مسارَين آخرَين — وقد بطل الاثنان بالقراءة.

**ومنعَ القياسُ قاعدةً كانت ستُشحَن بحسن نيّة**: عزلُ اسم المتغيّر بديلًا عن انتظار المنبع.
لا هي تُصلِح شيئًا، ولها ضررٌ محتملٌ على الصفّ اللاتينيّ (فقرةٌ LTR ⇒ «‎=‎» إلى الطرف
البعيد عن القيمة).

## م-٢١) حبرُ شجرة التنقيح لا يتبع مفتاحَ حجمِ خطّ الشريط الجانبيّ الذي يتبعه صفُّه

> ### ‏⬛ تصحيحٌ ثانٍ — وهذه المرّةَ في **الحكم** لا في التعليل وحدَه
>
> صُحِّح هذا البندُ مرّتين، والثانيةُ نقضت الأولى في موضعها الحرج. فيُسرَد التاريخُ
> كاملًا: بندٌ يُقرأ بعد ستّة أشهر ولا يعرف أنّه غُيِّر مرّتين يُعاد الاستدلالُ به
> على ما بطل.
>
> **التصحيحُ الأوّل (سالي).** كان النصُّ يقول «التشكيلُ مقصوص». والقياسُ أبطله: عند
> ‎13px‎ الحبرُ ‎15.2px‎ في صفٍّ ‎22px‎ ⇒ متّسع. والقصُّ يقع **بعد** حقن ‎15px‎ من
> الورقة، أي أنّه **عرَضُ العلاج الخاطئ لا عرضُ المرض**. وأُبدِل التعليلُ بخرق
> ‏WCAG ‎1.4.4‎: اللوحةُ صمّاءُ عمّن يحتاج حجمًا أكبر.
>
> **التصحيحُ الثاني (إيميليا).** وهذا نقضٌ للحكم: «صمّاءُ عن **كلّ** مفتاح» **غيرُ
> صحيحة**. ‏`VariablesDelegate.getHeight()` (‏`variablesView.ts:371`) يردّ
> ‏`FONT.sidebarSize22`، و`updateSidebarSize()` (‏`base/common/font.ts:166`) يشتقّه من
> ‏`workbench.sideBar.experimental.fontSize` (‏`sidebarPart.ts:42,354`). فارتفاعُ الصفّ
> **يتبع المفتاحَ سلفًا** — والحبرُ وحدَه لا يتبعه.
>
> **والنصُّ القديمُ تنبّأ بعطبه بنفسه**: خُتم بـ«لم نقرأ سطرَ الحساب في
> ‏`WorkbenchAsyncDataTree` بأنفسنا — يُقال ولا يُدَّعى». فلمّا قُرئ سقط الاستنتاج.
> وهذا وجهُ نفعِ تلك الجملة: حدٌّ مكتوبٌ يُوجِّه القارئَ التاليَ إلى موضع النقض.
>
> **وأثرُ النقضِ على المقترح جذريّ**: كان يطلب مفتاحًا عامًّا جديدًا
> ‏(`debug.variablesFontSize`) وارتفاعَ صفٍّ مشتقًّا منه — تغييرُ واجهةٍ عامّةٍ يُقاوَم
> ويُناقَش شهورًا. وصار **سطرَي CSS** يربطان الحبرَ بمتغيّرٍ منبعيٍّ قائمٍ يستهلكه سائرُ
> التنقيح أصلًا. أرخصُ بمراتب، وأقربُ إلى القبول، **وقد شُحن عندنا رقعةً**
> ‏(`031-debug-tree-font-size.patch`) لأنّه صار صغيرًا بما يكفي لأن يُشحَن.

**الحالُ في المنبع.** ‏`debug.contribution.css:90-102` يثبّت `font-size: 13px` (‏و‎11px‎
على mac) على `.debug-pane .monaco-list-row .expression`. وفي الملفّ نفسِه لا يوجد ما
يربطه بحجمِ خطّ الشريط الجانبيّ — بينما `debugToolBar.css:62-78` و`debugViewlet.css:385-395`
يشتقّان **كلَّ** مقاييسهما من `--vscode-workbench-sidebar-font-size`، وهو المتغيّرُ الذي
يضعه `sidebarPart.ts:358` على حاوية الشريط. فالشجرةُ هي **الاستثناء** لا القاعدة.

**والنتيجةُ مفارقةٌ لا نقصٌ بسيط.** ارتفاعُ الصفّ يتبع المفتاحَ والحبرُ لا يتبعه، فرفعُ
‏`workbench.sideBar.experimental.fontSize` من ‎13‎ إلى ‎20‎:

| المقيس | الصفّ | الحبر |
|---|---|---|
| المفتاح ‎13‎ (افتراض) | ‎22px‎ (‏13 × 22/13) | ‎13px‎ |
| المفتاح ‎20‎ | **‎33.8px‎** | **‎13px‎ — كما هو** |

أي أنّ من رفعه لأنّه لا يقرأ ‎13px‎ **يزداد فراغُه ولا يزداد مقروؤه**. وذلك أسوأُ من
عدم الاستجابة: يبدو أنّ المفتاحَ عمل، فيُصدَّق ولا يُبلَّغ عنه.

**والمقترح** سطران يتبعان ما يفعله سائرُ الملفّ:

```css
.monaco-workbench .debug-pane .monaco-list-row .expression {
	font-size: var(--vscode-workbench-sidebar-font-size, 13px);
}
.monaco-workbench.mac .debug-pane .monaco-list-row .expression {
	font-size: calc(var(--vscode-workbench-sidebar-font-size, 13px) * 11 / 13);
}
```

**ولا يقصّ عند أيّ حجم** — والبرهانُ نسبيٌّ لا عدديّ: الحبرُ المقيس ‎15.2px‎ عند ‎13px‎
⇒ ‎1.169em‎، وارتفاعُ الصفّ ‎22/13‎ ⇒ ‎1.692em‎. والنسبتان **ثابتتان في المُعامِل** لأنّ
الطرفين صارا يُضرَبان في القيمة نفسِها، فـ‎1.169S < 1.692S‎ عند كلّ ‎S‎. (وأرضيّةُ ‎1.88em‎
المقيسة في TY-02 أرضيّةُ **ارتفاع سطرٍ** لا ارتفاعِ حبر؛ وخلطُ الاثنين هو ما وَلَّد
استنتاجَ «يحتاج مفتاحًا جديدًا» في الصيغة السابقة.)

**ولماذا `calc` في قاعدة macOS ولا رقمٌ حرفيّ.** لو كُتبت `var(...)` وحدَها لقفز mac من
‎11px‎ إلى ‎13px‎ عند الافتراض — تغييرٌ في التصيير لم يطلبه أحد. وبالنسبة المحفوظة يخرج
‎13 × 11/13 = 11‎ بالضبط: **التصييرُ الافتراضيُّ مطابقٌ على المنصّتين**، ولا يرى فرقًا
إلّا من حرّك المفتاح. وهذا شرطُ قبولٍ عند المنبع قبل أن يكون ذوقًا.

**نطاقُه أوسعُ من العربيّة.** يصيب كلَّ من يحتاج حجمًا أكبرَ من ‎13px‎ — ضعافَ البصر
أوّلًا، وكلَّ كتابةٍ ذاتِ علاماتٍ فوقيّةٍ أو تحتيّة (العربيّة والفارسيّة والأردو والعبريّة
والتايلانديّة والفيتناميّة) ثانيًا. وهو **إصلاحُ وصولٍ** قبل أن يكون إصلاحَ اتّجاه.

**وما لا يبلغه هذا المقترحُ — يُقال ولا يُهرَّب.**

- **اللوحةُ السفلى**: من سحب «التشغيل والتنقيح» إلى اللوحة السفلى يخرج من نطاق
  المتغيّر (‏`panelPart` يستعمل `bottomPaneSize22` ولا يضع
  `--vscode-workbench-sidebar-font-size`)، بينما `getHeight()` يظلّ يقرأ `FONT.sidebarSize22`
  المُحجَّم ⇒ صفٌّ كبيرٌ بحبرٍ صغير. والقيمةُ الاحتياطيّة تُبقيه على حاله اليوم لا تُصلحه.
  إصلاحُه مقترحٌ ثانٍ (توحيدُ مصدرِ حجم الجزء) لا توسيعُ هذا.
- **نافذةُ التمرير** (`debug-hover-widget`) تعيش في المحرّر لا في الشريط، فتُترَك على
  ‎13px‎ عمدًا: ربطُها بمتغيّرِ الشريطِ الجانبيّ يربط سطحًا بمقياسِ سطحٍ آخر.

**وطريقٌ من الطبقة الأولى جُرِّب ذهنيًّا فسقط — ويُسجَّل كي لا يُعاد.** كان الظاهرُ أنّ
ضبطَ `workbench.sideBar.experimental.fontSize` في `configurationDefaults` من امتدادِ
‏`mihrab-shell` يكفي بلا رقعة. وهو **أخضرُ كاذبٌ مكتمل**: `getFontSize`
(‏`base/common/font.ts:118-131`) يفحص `inspect()` ويردّ الافتراضَ ما لم تكن القيمةُ في
‏`userValue`/`workspaceValue`؛ وافتراضاتُ الامتدادات تقع في `defaultValue`. فالقيمةُ
**تُقرأ في لوحة الإعدادات ولا تبلغ الشجرةَ إطلاقًا** — ‎15‎ في الإعداد و‎13‎ على الشاشة.

**سابقةٌ قبل الرفع.** **لم يُبحَث.**

## م-١٩) مُصنِّفُ الالتفاف يعرف CJK ويجهل العربيّة

**الحالُ في المنبع.** الاختيارُ بين حاسبَي الالتفاف يعتمد على `wrappingStrategy` وحدَها
(‏`viewModelLines.ts:308-313`) — لا على `fontInfo.isMonospace` ولا على `fontLigatures`.
وافتراضُ `editor.wrappingStrategy` هو `'simple'` (‏`editorOptions.ts:3082`) ⇒
`MonospaceLineBreaksComputer`. وفيه عطبان:

**(١) صنفُ المحرف.** `monospaceLineBreaksComputer.ts:81-97` — ما دون ‎256‎ من جدول ASCII،
وما فوقها يُفحَص **للصينيّة واليابانيّة وحدَهما** (‏CJK · الامتدادُ أ · الهيراغانا
والكاتاكانا) فيُعطى `BREAK_IDEOGRAPHIC`؛ والعربيّةُ (‏U+0600–U+06FF) تسقط إلى
`CharacterClass.NONE`. و`canBreak()` (‏`:517-527`) لا يسمح بكسرٍ إلّا عند حافّةِ
`BREAK_AFTER`/`BREAK_BEFORE` أو حدٍّ أيديوغرافيّ. فالنتيجة: **مقطعُ الالتفاف الوحيدُ في نصٍّ
عربيٍّ هو المسافة** — لا بعد «،» ولا بعد «؛»، بخلاف نظيرَيهما اللاتينيَّين `,` و`;`
المُدرَجَين في `wordWrapBreakAfterCharacters`.

**(٢) عرضُ المحرف.** `computeCharWidth()` (‏`:476-484`) يردّ ‎1‎ لكلّ محرفٍ عربيّ، لأنّ
`isFullWidthCharacter` يستثني العربيّةَ صراحةً (‏`strings.ts:724,729`:
`[IGNORE] FB50 - FDFF Arabic Presentation Forms-A` · `[IGNORE] FE70 - FEFF Arabic
Presentation Forms-B`). وقِسنا أنّ تقدُّم Kawkab Mono ‎0.70em‎ مقابل ‎0.60em‎ في مكدّس
السقوط — أي نحوَ ‎17٪‎ خطأٍ في كلّ عمود، **يتراكم كلّما طال السطر**.

**والمخرجُ القائم ليس مخرجًا.** `'advanced'` تُحيل الحسابَ إلى `domLineBreaksComputer.ts`
— أي إلى كاسر أسطر المتصفّح نفسِه (‏UAX #14)، وهو يعرف العربيّة. لكنّ المنبعَ يرفع
الاستراتيجيّةَ إليها تلقائيًّا **في حالةٍ واحدةٍ فقط**: حين يكون قارئُ شاشةٍ متّصلًا
(‏`editorOptions.ts:3102-3108`). أي أنّ كاتبَ العربيّة لا ينال التفافًا صحيحًا إلّا إن
شغّل قارئَ شاشة — **ترتيبٌ عرَضيٌّ بالكامل**، وكلفتُه معلنةٌ في المنبع نفسِه
(‏`wrappingStrategy.advanced`: «خوارزميّةٌ بطيئةٌ قد تُجمِّد الملفّاتِ الكبيرة»).

**المقترح.** شقّان مستقلّان، أوّلُهما وحدَه يُسقِط جُلَّ الأثر:

1. **صنفُ الكسر**: إضافةُ نقاط الكسر العربيّة إلى `WrappingCharacterClassifier` —
   `BREAK_AFTER` لِـ«،» (‏U+060C) و«؛» (‏U+061B) و«؟» (‏U+061F) و«۔» (‏U+06D4)،
   كما هي حالُ `,` و`;` و`?` اللاتينيّة. تغييرٌ في جدولٍ قائمٍ لا آليّةٌ جديدة.
2. **عرضُ المحرف**: أن يُشتقّ من `fontInfo` المقيسة بدل ثابتٍ في الشيفرة — أو، كحدٍّ
   أدنى، أن يُرفَع إلى `'advanced'` تلقائيًّا حين يعلم المحرّرُ أنّ الوجهَ **ليس أحاديَّ
   العرض** (‏`fontMeasurements.ts:207` يعرف ذلك بالفعل ويردّ `isMonospace = false`)،
   لا حين يُتّصل قارئُ شاشةٍ فقط.

**نطاقُه أوسعُ من العربيّة.** الشقُّ الأوّل يصيب كلَّ كتابةٍ غيرِ لاتينيّةٍ ولا صينيّة —
الفارسيّة والأردو والعبريّة والتايلانديّة — وهو **إصلاحُ عطبٍ لا ميزةٌ لمحراب**.

**صدقٌ واجب.** الدعوى مبنيّةٌ على قراءة المُصنِّف و`canBreak` و`computeCharWidth`؛ ومقارنةُ
مواضع الكسر بين `simple` و`advanced` على سطرٍ عربيٍّ طويلٍ **مِجَسٌّ مجدوَلٌ في موجة التنفيذ
الثالثة** ولم يُشحَن البندُ قبله.

**سابقةٌ قبل الرفع.** **لم يُبحَث.**

## م-٢٠) حالةُ «السوقُ غيرُ متاح» بلا نقطةِ امتدادٍ إطلاقًا

**الحالُ في المنبع.** لسوق الإضافات أربعُ حالاتٍ في
`extensionGalleryManifest.ts:71`، منها `Unavailable`. وهي **القيمةُ الافتراضيّةُ لمفتاح
السياق نفسِه** (`extensions.ts:260`):

```ts
export const CONTEXT_EXTENSIONS_GALLERY_STATUS =
  new RawContextKey<string>('extensionsGalleryStatus', ExtensionGalleryManifestStatus.Unavailable);
```

والعرضُ الوحيدُ الذي يقبل محتوى ترحيبٍ من إضافةٍ هو
`workbench.views.extensions.marketplaceAccess`، و`extensionsViewlet.ts:143-148` يسجّله
**بشرطٍ يستثني `Unavailable` صراحةً**:

```ts
when: ContextKeyExpr.and(
  ContextKeyExpr.or(ContextKeyExpr.has('searchMarketplaceExtensions'), ContextKeyExpr.and(DefaultViewsContext)),
  ContextKeyExpr.or(CONTEXT_EXTENSIONS_GALLERY_STATUS.isEqualTo(ExtensionGalleryManifestStatus.RequiresSignIn),
                    CONTEXT_EXTENSIONS_GALLERY_STATUS.isEqualTo(ExtensionGalleryManifestStatus.AccessDenied))
)
```

فحين يكون السوقُ غيرَ متاح **لا يوجد عرضٌ أصلًا** تُعلَّق عليه `viewsWelcome`. والذي يراه
المستخدمُ حينها نصٌّ يُكتَب **بإسنادٍ مباشرٍ إلى `textContent`** في
`extensionsViews.ts:1116-1119` و`:1130-1136` — «‏No extensions found.» أو «‏Unable to
search the Marketplace when offline…» — بلا نقطةِ امتدادٍ ولا محتوى ترحيبٍ ولا معرِّفِ
عرضٍ يُستهدَف.

**الأثرُ عندنا ‏[MK-01/ج].** أردنا أن نقول للمستخدم **ثلاثَ جملٍ لا واحدة**، لأنّ
الأسبابَ ثلاثةٌ مختلفةٌ تمامًا ويستحقّ كلٌّ منها فعلًا مختلفًا: (١) لا شبكة، (٢) شبكةٌ
تعمل و`open-vsx.org` لا يستجيب، (٣) الإضافةُ ليست في هذا السوق أصلًا (وهي الحالُ
الأكثرُ في Open VSX، ولا علاقةَ لها بعطب). ورسالةٌ واحدةٌ لثلاثة أسبابٍ تُعلِّم المستخدمَ
تجاهُلَها.

**والحدُّ بنيويٌّ لا نقصُ محاولة.** لا يمكن سدُّه من الطبقة الأولى: لا عرضَ يُستهدَف.
ولا من الطبقة الثانية: النصُّ ليس مسألةَ نمط. **فيُسجَّل قيدًا معلَنًا لا يُدَّعى تنفيذُه**
— وهذا أصدقُ من رقعةِ نواةٍ تاسعةٍ لأجل ثلاث جمل.

**المقترح.** تسجيلُ العرض في حالة `Unavailable` أيضًا، ووسمُ سببها في مفتاح سياقٍ
مستقلٍّ كي يفرّق محتوى الترحيب بين انقطاعِ الشبكة وتعذُّرِ السوق:

```ts
// (١) يُضاف Unavailable إلى شرط تسجيل العرض
ContextKeyExpr.or(
  CONTEXT_EXTENSIONS_GALLERY_STATUS.isEqualTo(ExtensionGalleryManifestStatus.RequiresSignIn),
  CONTEXT_EXTENSIONS_GALLERY_STATUS.isEqualTo(ExtensionGalleryManifestStatus.AccessDenied),
  CONTEXT_EXTENSIONS_GALLERY_STATUS.isEqualTo(ExtensionGalleryManifestStatus.Unavailable))

// (٢) ومفتاحُ سياقٍ يميّز السبب — تملكه المنصّة سلفًا في isOfflineError
export const CONTEXT_EXTENSIONS_GALLERY_OFFLINE = new RawContextKey<boolean>('extensionsGalleryOffline', false);
```

**نطاقُه أوسعُ من محراب.** يصيب **كلَّ توزيعةٍ تستبدل السوق** (‏VSCodium وOpen VSX
ونشراتِ المؤسّسات) وكلَّ مستخدمٍ خلف جدارٍ ناريّ — ولا يذكر عربيّةً ولا اتّجاهًا. وهو
عيبُ **قابليّةِ امتدادٍ** لا عيبُ ترجمة، فلا يُصلحه تراكبُ NLS: تعريبُ «‏No extensions
found.» يبقيها جملةً واحدةً لثلاثة أسباب.

**صدقٌ واجب.** القراءةُ من الشجرة المثبَّتة في `.upstream/` (‏`extensionsViewlet.ts`
و`extensionsViews.ts` و`extensions.ts`)، **ولم تُقَس حيًّا**: لم نقطع الشبكةَ على نسخةٍ
مشحونةٍ ولم نرصد ما يُصيَّر فعلًا في الحالات الثلاث. الدعوى دعوى بنيةٍ لا دعوى مشاهدة.

**سابقةٌ قبل الرفع.** **لم يُبحَث.**

> ### ‏⬛ تصحيحٌ: المقترحُ **لا يُطلَق في محرابٍ ولو قُبِل** — وصيغتُه تُعاد
>
> راجعت **إيميليا** هذا البندَ بنيّةِ نقضِ دعوى «مسدودٌ بنيويًّا»، فأيّدت السدَّ
> **وأسقطت المقترحَ نفسَه**. والفرقُ جوهريّ: البندُ يبقى مفتوحًا، والطريقُ المرسومُ
> لإغلاقه كان يؤدّي إلى لا شيء.
>
> **البرهان.** ‏`extensionGalleryManifestService.ts:30` يردّ الحالةَ **من وجود
> ‏`serviceUrl` وحدَه**:
>
> ```ts
> return !!this.productService.extensionsGallery?.serviceUrl ? Available : Unavailable;
> ```
>
> ومحرابٌ **يُصرّح** بـ`open-vsx.org` في `product-overrides/product.json` — وذلك من
> إنجاز `MK-01/أ` نفسِه. فالحالةُ عندنا **`Available` دائمًا**، ولو كانت الشبكةُ
> مقطوعةً والسوقُ ساقطًا. والأسبابُ الثلاثةُ التي كُتب هذا البندُ ليفرّقها تقع كلُّها
> تحت `Available` وتنتهي إلى `extensionsViews.ts:1116-1136`.
>
> ⇐ **مقترحٌ مبنيٌّ على `Unavailable` يُقبَل عند المنبع ويبقى البندُ مفتوحًا عندنا.**

## م-٢٢) قائمةُ فواصل الكلمة بلا علامةِ ترقيمٍ عربيّةٍ واحدة

**الحالُ في المنبع.** `editor/common/core/wordHelper.ts:10`:

```ts
export const USUAL_WORD_SEPARATORS = '`~!@#$%^&*()-=+[{]}\|;:\'",.<>/?';
```

إحدى وثلاثون علامة، **لاتينيّةٌ كلُّها**. ليس فيها الفاصلةُ العربيّة «،» ‏(U+060C) ولا
المنقوطةُ «؛» ‏(U+061B) ولا علامةُ الاستفهام «؟» ‏(U+061F) ولا النسبةُ «٪» ‏(U+066A) ولا
الوقفةُ «۔» ‏(U+06D4). وهي افتراضُ `editor.wordSeparators` (‏`editorOptions.ts:6763-6765`).

**والأثرُ يقع في كلّ سطرٍ يكتبه كاتبُ العربيّة، لا في حالةٍ نادرة.** النقرُ المزدوجُ على
«النتيجة» في `# اطبع النتيجة، ثمّ اخرج` يلتقط «النتيجة،» ومعها الفاصلة، فتُلصَق في اسم
متغيّرٍ فينكسر. و‏Ctrl+←/→ يقفزان الجملةَ كلَّها لأنّ لا فاصلَ في طريقهما. والمساران
يمرّان بالمِسطرة نفسِها ولا ينقذهما `wordPattern` الخاصُّ بإعداد اللغة: النقرُ المزدوجُ
‏`coreCommands.ts:1658` ⇐ `cursorWordOperations.ts:741-742`، والتنقّلُ `moveWordLeft/Right`
— وكلاهما يأخذ `WordCharacterClassifier` المبنيَّ من `wordSeparators`.

**ولا يُصلحه `wordSegmenterLocales`.** قِيس المسارُ الثاني (‏`Intl.Segmenter`) على أربعَ
عشرةَ سلسلةً بـ`["ar"]` ثمّ `["en"]` ثمّ الجذر: **متطابقةٌ حرفًا**، لأنّ تجزئةَ ICU تتبع
‏UAX#29 المحايدةَ للغة ولا تُستدعى المعاجمُ إلّا لـ‏th/lo/km/my/ja/zh. فهو ليس «تجزئةً
عربيّة» بل تشغيلُ UAX#29 — ويجرّ معه تغيُّرًا في النحو اللاتينيّ (النقطةُ `MidNumLet`
فيلتقط النقرُ على ‎`3.14`‎ العددَ كلَّه). فالحلُّ الصحيحُ في القائمة لا في المُجزِّئ.

**المقترح.** إضافةُ علامات الترقيم العربيّة إلى `USUAL_WORD_SEPARATORS`. والمعيارُ
الذي طبّقناه عندنا ونقترحه: يُضاف المحرفُ إن كان علامةَ ترقيمٍ في النثر، ويُستثنى إن
كان فاصلَ **عدد**. فتُضاف `، ؛ ؟ ٪ ۔ ؞ ؍ ٭`، و**تُستثنى** «٫» ‏(U+066B) و«٬» ‏(U+066C)
لأنّهما نظيرا الفاصلة العشريّة وفاصلة الآلاف داخل الأرقام، وإضافتُهما تشقّ ‎٣٫١٤‎.

**والخطرُ المتوقَّعُ مُكذَّبٌ قياسًا.** الشرطةُ السفليّة تبقى رابطةً في الحالتين
(‏`نصاب_الفضة` · `snake_case_name` لا تُشقّان)، وأربعُ حالاتِ مُعرِّفاتٍ ضابطةٍ لم تتغيّر.

**ولماذا يستحقّ المنبعُ لا كلَّ تثبيتٍ على حدة.** القيمةُ سُلَّميّةٌ من نوع `string`،
فتجاوزُها **يستبدل** الافتراضَ ولا يضيف إليه. أي أنّ كلَّ مستخدمٍ يريد فاصلةً عربيّةً
مضطرٌّ إلى **نسخ الإحدى والثلاثين علامةً اللاتينيّة نسخًا حرفيًّا** ثمّ الزيادةِ عليها،
وإلى إعادةِ النسخ كلّما زاد المنبعُ علامة. وهذا عبءٌ لا يحتمله مستخدم، ونحن نحمله عنه
بحارسٍ يشتقّ البادئةَ من `wordHelper.ts` ويسقط عند الانجراف — وهو حلٌّ يصحّ لمستودعٍ
لا لملايينِ التثبيتات.

**وهو إصلاحُ عطبٍ يصيب غيرَ العربيّة أيضًا**: الفارسيّةُ والأرديّةُ والباشتو تستعمل
هذه العلاماتِ نفسَها.

## م-٢٣) حاسبُ الكسر الأحاديّ يعدّ علامةَ التشكيل عرضًا

**الملفّ**: `src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts:81-97`
**الحال**: عند حساب مواضع كسر السطر بالمِسطرة الأحاديّة (`editor.wrappingStrategy: "simple"`،
وهو **الافتراض**)، يُحتسَب لكلِّ نقطةِ ترميزٍ عرضٌ قدرُه ‎1‎. ومحارفُ التشكيل العربيّة
(‏`U+064B`–`U+0652`، وسائرُ صنف `Mn` في يونيكود) **عرضُها صفرٌ عند الرسم** — تُركَّب على
الحرف السابق ولا تزيد تقدُّمَ القلم. فيُبالَغ في تقدير عرض السطر بمقدار عدد العلامات فيه،
ويُكسَر مبكّرًا.

**الأثرُ مقيسٌ لا مُقدَّر.** على خطٍّ أحاديِّ العرض حقًّا (‏Kawkab Mono: كلُّ محرفٍ أساسيّ
‎700‎، والتشكيلُ ‎0‎، مقروءًا من `hmtx`)، وبقياس **نسبة الملء** = حبرُ سطرِ العرض ÷ عرضِ
منطقة المحتوى:

| العيّنة | `simple` | `advanced` |
|---|---|---|
| عربيّةٌ خالصةٌ بلا تشكيل | ‎95%‎ | ‎95%‎ |
| تشكيلٌ خفيف (ثلثُ الكلمات) | ‎85%‎ | ‎95%‎ |
| **تشكيلٌ كامل** | **‎50%‎** | **‎95%‎** |

أي أنّ نصفَ عرض الشاشة يذهب بياضًا في النصّ المُشكَّل. والتطابقُ التامُّ في الصفّ الأوّل
هو الشاهدُ على أنّ العلّةَ **التشكيلُ وحدَه** لا «العربيّةُ متغيّرةُ العرض»: فالمِسطرتان
تتّفقان حرفيًّا حين يغيب التشكيل.

**والعلاجُ المتاحُ اليومَ لا يناسب**: `editor.wrappingStrategy: "advanced"` يفوّض الحسابَ
للمتصفّح فيصيب، لكنّه قِيس عند ‎≈0.17‎ مللي لكلِّ سطرِ نموذج — حجبًا **متزامنًا** للخيط
الرئيسيّ عند فتح الملفّ (‎0.184‎ · ‎0.173‎ · ‎0.167‎ عند ‎500‎ و‎1500‎ و‎3000‎ سطر، خطّيًّا).
أي نصفُ ثانيةٍ تجمُّدًا على ‎3000‎ سطر وخمسُ ثوانٍ على ‎30‎ ألفًا. والمنبعُ نفسُه يصفه
بأنّه «قد يُجمِّد الملفّاتِ الكبيرة» (‏`editorOptions.ts:3087`) — فهو تبديلُ عطبٍ بعطب.

**المقترح**: أن يتخطّى الحاسبُ الأحاديُّ محارفَ صنف `Mn` (أو، بأدنى كلفة، مدياتِ التشكيل
العربيّ والعبريّ والهنديّ) فلا يحتسب لها عرضًا. الكلفةُ فحصُ مدًى واحدٌ لكلِّ نقطةِ ترميز،
وهو لا شيءَ بجانب ‎0.17‎ مللي/سطر.

**ولماذا يستحقّ المنبعُ لا كلَّ تثبيتٍ على حدة**: لا يوجد إعدادٌ وسط. الخياران المتاحان
للمستخدم هما «مِسطرةٌ خاطئةٌ رخيصة» و«مِسطرةٌ صائبةٌ قد تُجمِّد» — والصوابُ الرخيصُ ممكنٌ
وليس مطروحًا. ولا سبيلَ لقصر `wrappingStrategy` على حجم الملفّ:
‏`largeFileOptimizations` (‏‎20‎ م.ب / ‎300‎ ألفِ سطر، `textModel.ts:189`) **لا تمسّه** إطلاقًا.

**وهو إصلاحُ عطبٍ يصيب غيرَ العربيّة**: العبريّة (النِّقّود)، والديفاناجاري والتاميل
والتايلانديّة (علاماتُها التركيبيّة)، وكلُّ لاتينيٍّ مكتوبٍ بصيغة NFD — كلُّها تُحتسَب
اليومَ عرضًا وهي بلا عرض.

## م-١٨ — حسابُ أعمدةِ الطرفيّة يفترض اليسار

**العطب.** ‏`xterm.js` بلا أيّ دعمٍ للاتّجاه ثنائيِّه — بحثُ `bidi|rtl` في مصدره
يعطي صفرَ نتائج. ولا يقتصر الأمرُ على غياب ميزة: **رياضيّاتُ الإحداثيّات تفترض
اليسارَ افتراضًا صلبًا**، فحتّى من يقلب التخطيطَ بورقة أنماطٍ من خارج المكتبة يقع
في عطبٍ أسوأ من الأصل.

| الموضع | الحاليّ |
|---|---|
| `src/browser/input/Mouse.ts` | `clientX - rect.left - paddingLeft` |
| `src/browser/renderer/dom/DomRenderer.ts` | `left = colStart * cellWidth` |

**الأثرُ المقيس.** بعد قلب التخطيط، نقرةٌ مزدوجةٌ عند `x=975` على أوّل حرفٍ عربيٍّ
تُنتج مستطيلَي تحديدٍ عند `x=368` و`x=166`. **فالمستخدمُ يرى نصًّا ويحدّد غيرَه** —
وهذا أسوأُ من عرضٍ مقلوبٍ يعرف صاحبُه أنّه مقلوب.

**المقترَح.** أن تعرف طبقةُ العرض اتّجاهَ الصفّ (‏من أوّل محرفٍ قويٍّ فيه، وهي قاعدةُ
المواصفة نفسُها التي يطبّقها `unicode-bidi: plaintext`)، وأن تُشتقَّ منه إزاحةُ
العمود: من اليمين للصفّ اليمينيّ ومن اليسار لغيره. والأتمُّ منه خريطةُ ترتيبٍ
بصريٍّ ⟷ منطقيٍّ لكلّ صفّ، فتصحّ **السطورُ المختلطة** كذلك لا العربيّةُ الخالصةُ وحدَها.

**ما نفعله ريثما يُرفَع.** ‏`build/patch_xterm_bidi.py` يرقّع الحزمةَ **المشحونة**
(‏`lib/xterm.js` المبنيّ المصغَّر) بعد الحزم — لا `node_modules` قبل البناء، لأنّ
`npm ci` يمسحه. وثلاثةُ أسيجة: حارسُ إصدارٍ مثبَّت، وكلُّ مِرساةٍ مرّةً واحدةً وإلّا
أُجهض البناء، ووسمُ تكرار. **والرقعةُ مرآةٌ حسابيّة**: صحيحةٌ على السطر العربيِّ
الخالص، **تقريبيّةٌ على المختلط** — وهذا هو الفرقُ الذي يُسقطه رفعُ المقترَح.
